0. 场景设定与 CP 的本质

维度取值说明
world_size8TP=4 × CP=2
CP2序列切成 2 段，2 卡各算一段
序列长度 L8192每卡局部 4096
attention.backendFlexAttentionCP 用 gather-KV 方案（见下）
🎯 CP 要解决什么 序列太长，单卡放不下 KV cache。CP 把序列维切给多卡，每卡只算自己那段序列的 attention。 但 attention 的 q·kᵀ 要看到完整 key——所以 CP 的通信点集中在：切序列（输入） + gather 完整 k/v（注意力内部）。

1. 第 1 层 · 用户层：声明 CP 的激活布局

CP 的声明不做在"模型权重"上，而是做在激活布局和内部注意力的 k/v上（models/common/decoder_sharding.py）：

# ① 通用激活布局：CP 默认把序列维 Shard(1)（decoder_sharding.py:34-50）
def dense_activation_placement(*, tp, cp=spmd.S(1)):   # ← 关键默认值
    return SpmdLayout({DP: spmd.S(0), CP: cp, TP: tp})
#   真实值：x_BLD 在 CP 轴上是 Shard(1)（序列维切分）

# ② 内部注意力：q 保持 CP 切分，k/v 却在 CP 上 all-gather（decoder_sharding.py:200-203）
q_placements      = dense_activation_placement(tp=spmd.S(2))                # q：CP 保持 S(1)
kv_src_placements = dense_activation_placement(tp=spmd.S(2))                # k/v 进来：CP:S(1)
kv_dst_placements = dense_activation_placement(tp=spmd.S(2), cp=spmd.R)  # k/v 进 kernel 前：CP gather 成 R
#   真实值：这里就是 "gather-KV" 的声明——q 分块算，k/v 聚合给 kernel 看完整 key

# ③ deepseek_v3/sharding.py:98-105 —— attention 模块入口 x 的 CP 声明
attention.sharding_config = ShardingConfig(
    in_src_shardings={ "x": attn_x_layout },     # 进来：CP:S(1)（序列切分）
    in_dst_shardings={ "x": dense_activation_placement(tp=spmd.R) },  # TP gather，但 CP 仍是 S(1)！
)
#   真实值：模块级 in_dst 故意不动 CP（CP 靠内部 local_map 处理，见 3.2）

用户层 = 3 条布局声明：① 激活 CP 切片；② 内部注意力的 q/k/v 布局；③ 模块入口 x 布局。 注意第 ②③ 步就是之前回答"为什么 TP 聚合而非 CP"的关键——CP 的聚合发生在 inner attention 的 kv_dst 里。

2. 第 2 层 · Titan 层：切输入 / 包 forward / 负载均衡

2.1 切分输入（trainer 每步调用 prepare_context_parallel_input）

# trainer.py:701-710 → context_parallel/api.py:114-163
inputs, labels, extra_kwargs = prepare_context_parallel_input(
    inputs, labels, extra_kwargs,
    self.parallel_dims.get_mesh("cp"),   # cp_mesh = size 2
    self.device, load_balancer_type="ptrr")
# → cp_shard()：调用 torch.distributed.tensor.experimental._attention 的 _context_parallel_shard
#   把 inputs/labels/positions 沿序列维 shard 给 CP=2 卡
#   真实值：inputs (B, 8192) → (B, 4096) 每卡

2.2 包装 inner attention（apply_cp_to_forward）

CP 的 forward 包装必须在 Module.parallelize() 之前调用， 才会被 local_map 包裹（context_parallel/api.py:35-78）：

# models/deepseek_v3/parallelize.py:76-81
if parallel_dims.cp_enabled:
    apply_cp_to_forward(
        [block.attention.inner_attention for block in model.layers.values()],
        parallel_dims.get_mesh("cp"),
    )

# api.py:57-78 —— FlexAttention 分支
def _make_cp_forward(orig_fn, mesh):
    pg_name = dist._get_process_group_name(mesh.get_group())   # CP 进程组
    def cp_forward(q, k, v, **kwargs):
        k = k.contiguous(); v = v.contiguous()
        global_k, global_v = flex_cp_allgather(k, v, 1, pg_name)   # ← 关键：序列维 all-gather
        return orig_fn(q, global_k, global_v, **kwargs)
    return cp_forward
mod.forward = _make_cp_forward(original_forward, cp_mesh)
🔀 顺带一提：负载均衡 CP 会切序列，但因为 attention 的因果性，每段序列的注意力负载不均（前面的段要看的 key 少）。 torchtitan 用 load balancer 解决：PTRR（FlexAttention）或 HeadTail（SDPA）在 cp_shard 里把切分点挪匀 （api.py:217-259）。这也是 CP 特有、TP 没有的额外逻辑。

3. 第 3 层 · Torch 层：序列切分与 k/v gather

CP 的两个通信动作都发生在 PyTorch：

# ① 输入切分 —— _context_parallel_shard（torch.distributed.tensor.experimental._attention）
#    真实值：inputs (B, 8192) → 每卡 (B, 4096)，用 Shard(1) 于 CP mesh

# ② k/v all-gather —— flex_cp_allgather（api.py:21-23 导入）
global_k, global_v = flex_cp_allgather(k, v, 1, pg_name)
#    真实值：k/v 在序列维(S(1)@CP)上 all-gather → 每卡拿到完整 k/v

图示（CP=2，L=8192，每卡 4096）：

卡0：q = seq 0..4095
卡1：q = seq 4096..8191
k 卡0：0..4095
k 卡1：4096..8191
→ all-gather →
k 卡0：0..8191
k 卡1：0..8191
⚙️ 为什么 q 不 gather、只 gather k/v q 每卡只算自己那段序列的注意力，所以 q 保持 Shard(1)； 但 q·kᵀ 要对整条序列的 key 算——所以只把 k/v 在 CP 上 all-gather。 这正是"gather-KV（GCP）"方案，也是 CP 与"切头不切序列"的 TP 最本质的区别。

4. 全链路流转 + CP vs TP

1
用户声明：激活 CP 切片（dense_activation_placement(cp=S(1))）+ 内部注意力 q/k/v 布局。
2
Titan切输入：prepare_context_parallel_input → _context_parallel_shard 把序列 shard 给 CP=2 卡，并做负载均衡。
3
Titan包 forward：apply_cp_to_forward 在 parallelize 前包装 inner attention，注入 k/v all-gather。
4
Torch内部 k/v all-gather：flex_cp_allgather 把 k/v 沿序列维聚合，q 保持分块。
5
Torch注意力计算：每卡用局部 q × 完整 k/v 算自己的那段，互不干扰。
维度CP（上下文并行）TP（张量并行，对比）
切什么序列维 S(1)头维/特征维
q 的布局保持切分（分块算）序列完整、头切分 S(2)
k/v序列维 all-gather（gather-KV）头切分，CP 上再 gather
通信动机省 KV 显存省计算/权重显存
特有逻辑负载均衡（PTRR/HeadTail）colwise/rowwise 权重切分
