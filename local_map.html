local_map 是什么 · 在哪儿用

torchtitan 声明式并行中的「本地计算区」机制 · 图解版（基于 D:\02_source\torchtitan 源码）

① 核心机制：DTensor 边界 + 本地计算区（两条路径）

② 实现链：从声明到运行

③ 重点拆解：GQA 内注意力（TP × CP 叠加）

④ 使用全景：local_map 在仓库里覆盖了哪些地方

⑤ MoE 使用点拆解：RoutedExperts 本地区

⑥ 使用注意事项（踩坑点）

① 顺序约束：CP 包装（apply_cp_to_forward）必须在 parallelize() 之前调用；否则 CP 逻辑跑在 local_map 边界外，拿到的是 DTensor 而非本地张量，直接出错（context_parallel/api.py:41-42、llama3/parallelize.py:47-54 注释）。
② 声明必须成对：设了 local_map 就必须同时给全 in_dst_shardings（覆盖 forward 全部位置参数，缺一个就抛 AssertionError）和 out_src_shardings（module.py:435-445）。
③ 非张量参数用 None 占位：在 in_grad_placements 里对非张量参数填 None（原样透传、mesh 解析时过滤，module.py:469-471）；MoE 的路由元数据虽是元数据但仍是 DTensor 输入，也必须给 placement（moe_sharding.py:256-259）。
④ 双后端别混用：DTensor 后端用 torch.distributed.tensor.experimental.local_map（placement 元组），spmd_types 后端用 spmd.local_map（in/out_types 字典），由 parallel_dims.spmd_backend 选择（module.py:448-450）。

语义总结：src = 「当前/声称是什么布局」，dst = 「要变成什么布局」。输入侧只搬到本地区需要的 in_dst（这正是 local_map 的 in_placements）；输出侧 local_map 已按 out_src 包回 DTensor，再搬到 out_dst 交给下一个模块。src 侧还承担「声明事实」职责——普通张量靠 from_local 标注、DTensor 靠校验确认。

⑨ 深挖 Q3：local_map 怎么实现的？最终调的是 PyTorch 接口吗？

是。 torchtitan 自己没有实现 local_map —— 它只是把参数包装好，最终调用 PyTorch 的 torch.distributed.tensor.experimental.local_map（module.py:20 import、module.py:490 调用）。PyTorch 2.12.1 的实现就在 torch/distributed/tensor/experimental/_func_map.py：

结论：torchtitan 的 local_map 最终调用的就是 PyTorch 接口（torch.distributed.tensor.experimental.local_map），它自己只做「参数装配」（把 in_dst/out_src/in_grad_placements 解析成 placement 元组并解析 mesh，module.py:473-495）。PyTorch 侧 _local_map_wrapped 再走 to_local → fn → from_local 三步，底层原语仍是 DTensor 的 to_local / from_local / redistribute。另外当 spmd_backend == "spmd_types" 时走的是另一套 torch.distributed.tensor.experimental.spmd.local_map（按类型字典 in_types/out_types 声明，module.py:498-516），机制类似但基于类型系统。

⑩ 深挖 Q4：什么时候该用 local_map？谁会真的变成本地张量？

先纠一个常见误解：_redistribute_inputs 不负责「DTensor → 本地张量」。它做的只是 DTensor 布局之间的搬运（如 Shard(1) → Replicate），张量全程保持 DTensor 身份；「卸成本地」是 local_map 边界里 to_local() 的职责（_func_map.py:216-226）。两者是不同概念、不同代码路径。

⑪ 深挖 Q5：用户在哪儿设置？转换在哪儿发生？啥也不设置会怎样？

最小示例 —— 你自己写模型时怎么声明 local_map：

# 模型作者的 sharding helper（如 my_model/sharding.py）
def set_my_model_sharding(config, ...):
    # 需要本地计算区的模块：填 in_dst + out_src + local_map 三件套
    config.inner_attn.sharding_config = ShardingConfig(
        in_dst_shardings={"q": q_layout, "k": k_layout, "v": v_layout},
        out_src_shardings=out_layout,
        local_map=LocalMapConfig(in_grad_placements=(q_layout, k_grad, v_grad)),
    )
    # 纯算子模块：不填 local_map，靠 DTensor 分发
    config.linear1.sharding_config = colwise_config()   # 只有 state + out_src
    # 不填的模块：不参与这套体系，原样运行
