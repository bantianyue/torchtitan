0. 场景设定与 EP 的本质

维度取值说明
world_size8EP=4 × TP=2（MoE 组内）
EP4160 个专家切成 4 份，每卡 40 个专家
num_experts160DeepSeek-V3 路由专家数
专家权重形状w1_EFD: (160, 1536, 5120)E=专家，F=中间维，D=隐藏维
top_k6每个 token 路由到 6 个专家
🎯 EP 要解决什么 MoE 专家很多（160 个）放不下。EP 把"专家"本身分到不同卡——每卡只存一部分专家的权重。 但每个 token 可能被路由到"别人卡上的专家"，所以必须用 all-to-all 把 token 送到持有对应专家的卡上， 算完再送回来（combine）。这是唯一一种"数据跟着计算走"的并行。

2. 第 2 层 · Titan 层：稀疏 mesh + token 分发

2.1 建稀疏 FSDP mesh（full_dtensor.py:109-125）

def resolve_sparse_fsdp_mesh(parallel_dims) -> (DeviceMesh | None, DataParallelMeshDims):
    if not parallel_dims.ep_enabled: return None, None
    sparse_mesh = parallel_dims.get_activated_mesh(["dp_replicate", "efsdp", "ep"])
    # 真实值：稀疏 mesh = (dp_replicate, efsdp, ep)，专家权重在这个稀疏 mesh 上 FSDP
    return sparse_mesh, DataParallelMeshDims(shard="efsdp", replicate="dp_replicate")

3. 第 3 层 · Torch 层：all-to-all + 专家权重切分

EP 的执行核心：token 分发（all-to-all）+ 专家权重 EP 轴切分。

# ① token 分发 —— AllToAllTokenDispatcher（token_dispatcher.py:203-248）
def _token_count_exchange(self, num_local_tokens_per_expert_E, pg, ep_size):
    return all_to_all_single(
        num_local_tokens_per_expert_E.view(ep_size, -1), None, None, group=self.ep_mesh)
#    真实值：先交换每卡每专家的 token 数（决定切分），再做数据 all-to-all

# ② 专家权重本身 —— inner_experts（GroupedExperts）的权重是 DTensor，沿 EP 轴 Shard(0)
#    w1_EFD (160,1536,5120) @ EP=4 → 每卡局部 (40,1536,5120)，placements = (Shard(0)@EP)

# ③ combine —— 送回来的 token 乘权重分数再 scatter_add 回原位（moe.py:172-176）
out_TD = self.token_dispatcher.combine(routed_output_RD, metadata, x_TD)  # 反向 all-to-all
⚙️ EP 的通信是 all-to-all（唯一） all-to-all vs all-gather / reduce-scatter 的本质区别：后两者是"广播/求和"（每卡拿相同结果）， 而 all-to-all 是"交换"（每卡把自己的 token 送给对应专家所在的卡，同时收到别人发来的 token）。 这是 EP 独有的、数据跟着计算走的模式。
另外 EP 的专家权重还叠加 FSDP（稀疏 mesh 上的 efsdp 轴），所以专家权重最终是 EP 切专家维 × FSDP 切参数维的"混合切分"。

4. 全链路流转 + EP vs TP

1
用户声明：专家权重 expert_param_placement_sparse（EP 切专家维）+ 路由计数 Partial + token 输入布局。
2
Titan建稀疏 mesh：resolve_sparse_fsdp_mesh 得到 (dp_replicate, efsdp, ep) mesh。
3
Titan分专家权重：_shard_placement_fn 把专家权重放到稀疏 mesh（EFSDP+EP），其它参数放稠密 mesh。
4
Titanwire EP mesh：RoutedExperts.parallelize 注入 EP mesh 到 token dispatcher。
5
Torchall-to-all 分发：把 token 送到持有目标专家的卡上；专家权重沿 EP 轴 Shard(0) 计算。
6
Torchall-to-all 收回 + combine：结果送回原卡，乘以路由分数并 scatter_add。
对比EP（专家并行）TP（张量并行）
切的对象专家（token 路由到的专家分卡）单个权重维度（colwise/rowwise）
通信类型all-to-all（数据跟着计算走）all-gather / reduce-scatter
数据是否跨卡是（token 来回传送）否（每卡算自己的分片）
布局来源expert_param_placement_sparse（EP 轴）colwise/rowwise_config（TP 轴）
是否叠加 FSDP是（稀疏 mesh efsdp 轴，混合切分）有（稠密 mesh）
💡 一句话串起三层 用户声明专家权重布局 + 路由；Titan建稀疏 mesh、分专家权重（di FF），并把 EP mesh 注入 token dispatcher； Torch 的 all_to_all_single 把 token 送到专家所在的卡算完再送回。EP 是唯一用 all-to-all 的并行。
