0. 场景设定与 PP 的本质

维度取值说明
PP 卡数44 个 stage，每个 stage 放一部分层
模型层数60DeepSeek-V3 decoder 层
层/卡1560 / 4 = 15 层每卡
microbatch8一个 batch 切成 8 个 micro-batch 流水
scheduleGPipe / 1F1B用户指定调度（见下）
🎯 PP 要解决什么 模型太大，单卡放不下全部层。PP 把模型按层分成几段（stage），每段放一张（或多张）卡。 数据以 microbatch 为单位在一个接一个的 stage 里流水推进。PP 和 TP/CP/FSDP 完全不同： 它切的是"层"，不是"单个 tensor 的维度"，通信是 stage 之间的 P2P 传激活。

1. 第 1 层 · 用户层：只声明调度参数

PP 的用户层配置全在 ParallelismConfig 里（不需要写 per-param 分片）：

# ParallelismConfig —— 用户声明 PP 的"形状"
pipeline_parallel_degree        = 4   # 4 个 stage
pipeline_parallel_schedule     = "1F1B"   # 或 "GPipe"/"Interleaved1F1B"/"DualPipe"/"ZBV"
pipeline_parallel_layers_per_stage = 15   # 每 stage 15 层（也可自动算）
pipeline_parallel_microbatch_size = 8   # batch 切成 8 个 micro-batch
module_fqns_per_model_part      = None   # 可手动指定 stage 模块，默认自动切

用户不写"哪层放哪卡"——torchtitan 用 _generate_llm_fqn_per_model_part（pipeline_parallel.py:366-476） 按层数 + 首尾权重自动把 tok_embeddings / layers.* / norm / lm_head 分到各 stage。 这就是用户层的全部：一个调度字符串 + 两个整数。

2. 第 2 层 · Titan 层：pipeline_llm 切模型建调度

# trainer 初始化时调用 pipeline_llm（pipeline_parallel.py:65-141）
pp_mesh = parallel_dims.get_mesh("pp")   # 1 维 mesh，size=4

# ① 决定每 stage 放哪些模块（默认自动切）
module_names_per_stage = _generate_llm_fqn_per_model_part(4, 60)
#   真实值（近似）：stage0=["tok_embeddings","layers.0".."layers.13"],
#                   stage1=["layers.14".."layers.28"], stage2=["layers.29".."layers.43"],
#                   stage3=["layers.44".."layers.59","norm","lm_head"]

# ② 切模型：每一卡创建属于自己 stage 的模型副本（_split_module 深层拷走指定模块）
stages, model_parts = _pipeline_module_split(
    model, pp_mesh, schedule, device, module_names_per_stage, get_mesh=get_mesh_cb)

# ③ 每个 stage 内部再套其它并行：每个 model_part 单独跑 TP/FSDP/EP 的 parallelize_fn
for i, m in enumerate(model_parts):
    m = parallelize_fn(m, parallel_dims=parallel_dims, ...)   # 各自 apply TP/FSDP/EP
    stages[i].submod = m

# ④ 组装调度器（_build_pipeline_schedule）
pp_schedule = _build_pipeline_schedule(
    parallelism=parallelism, local_batch_size=..., stages=stages, loss_fn=loss_fn)
#   真实值：1F1B schedule，n_microbatches = batch_size / microbatch_size = 8

训练时：trainer 用 schedule 驱动（trainer.py:775-811）

def pp_forward_backward_step(self, input_dict_mbs, label_mbs, global_valid_tokens):
    ...
    self.pp_schedule.step(
        arg_mbs=arg_mbs,      # 8 个 microbatch 的输入
        kwarg_mbs=kwarg_mbs,
        target_mbs=target_mbs,
        losses=losses,
        loss_kwargs=loss_kwargs,
        return_outputs=False)
    # schedule.step 内部逐 microbatch 依次前向/反向，跨 stage 传激活
🔀 PP + FSDP 的联动 get_fsdp_reshard_after_forward_policy（fsdp.py:66-74）在 PP 开启时默认 not pp_enabled = False（不 reshard）——避免每个 microbatch 都做一次 all-gather 的开销。 这是 PP 特有的对 FSDP 策略的修改。

3. 第 3 层 · Torch 层：PipelineStage + P2P 通信

PP 的实际执行靠 torch.distributed.pipelining：

# ① 每个 stage 被包装成 PipelineStage（pipeline_parallel.py:634-641）
stage = PipelineStage(
    model_chunk, stage_idx, num_stages, device,
    group=pp_mesh.get_group("pp"),   # PP 进程组 → 定义相邻 stage 间的 P2P 通道
    get_mesh=get_mesh,               # 重建 DTensor 用（见下）
)

# ② schedule.step() 里：相邻 stage 之间用 P2P send/recv 传激活张量
#    stage i 前向完 → send(输出激活) → stage i+1 recv() 接着算
#    反向同理，从后往前传梯度

# ③ DTensor 跨 stage 重建（_build_get_mesh_callback，pipeline_parallel.py:41-62）
def _get_mesh(mesh_dim_names, mesh_layout):
    mesh = parallel_dims.get_mesh(list(mesh_dim_names))   # 得到本 stage 的本地 DeviceMesh
    ...
    return mesh
#   真实值：DTensor 不能直接跨 stage 序列化（ProcessGroup 不可序列化），
#           所以每卡收到前一 stage 的 plain tensor 后，用这个回调重建本地 DeviceMesh，
#           再把张量包回 DTensor 并赋予正确 placements。

microbatch 流水示意（1F1B，纵深 = 4 stage）

t=0m0 f---
t=1m1 fm0 f--
t=2m2 fm1 fm0 f-
t=3m3 fm2 fm1 fm0 f
t=4m0 bm3 fm2 fm1 f
t=5m1 bm0 bm3 fm2 f
t=6m2 bm1 bm0 bm3 f
t=7m3 bm2 bm1 bm0 b

f = 前向   b = 反向 —— 1F1B（one forward one backward）在气泡（bubble）阶段交错前向/反向，提高利用率。每一格表示一个 stage 上的一个 microbatch 阶段。

⚙️ PP 的通信只有 P2P 与 TP/CP/FSDP 的 collective 通信不同，PP 跨 stage 是点对点 send/recv（相邻 stage 传激活/梯度）。 而 PP 之内每个 stage 还可以嵌套 TP/FSDP/EP——所以 PP 是"最外层"的并行划分， 在 parallelize_fn 里逐个 stage 再套其它并行。

4. 全链路流转 + PP 与其它并行的关系

1
用户声明：pipeline_parallel_degree/schedule/layers_per_stage/microbatch_size。无 per-param 声明。
2
Titan切模型：_generate_llm_fqn_per_model_part 决定每 stage 模块 → _pipeline_module_split 建 4 个 stage。
3
Titan套内层并行：逐个 model_part 跑 parallelize_fn（TP/FSDP/EP 作用于每个 stage 内部）。
4
Titan建调度：_build_pipeline_schedule 组装 1F1B schedule；训练时 pp_schedule.step 驱动 microbatch 流水。
5
TorchP2P 通信：PipelineStage 用 PP 进程组在相邻 stage 间 send/recv 激活与梯度；DTensor 经回调重建。
对比PP（流水并行）TP / FSDP / EP
切的对象模型层（stage）单个 tensor 的维度 / 权重
通信类型stage 间 P2P send/recvcollective（all-gather/reduce-scatter/all-to-all）
单位microbatch（流水）每个 forward/backward
是否需 per-param 分片不写TP/EP 要写，FSDP 不写
与其它并行关系最外层，可嵌套其它并行在 PP stage 内部生效
