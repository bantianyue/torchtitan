# 2026-10-13

## 换机计划取消，回到本机跑混合并行

用户反馈换机失败，只能在本机（i7-1165G7 / 4 核 8 线程 / 16 GiB / 无 GPU）继续。
诉求：给出几个**本机可用**的混合并行方法。

把 `run_cpu_train.py` 的策略预设从 TinyGPT 换到 **Qwen3.5-0.8B** 上实测，
发现三个约束是**关于模型**而不是关于机器的，把混合空间砍掉一大半。

### 三个硬约束（模型层面）

1. **PP 不能开 weight tying** —— `torchtitan/models/common/decoder.py` 在
   `enable_weight_tying and pipeline_parallel_degree > 1` 时直接
   `raise NotImplementedError`。**这是架构性的，不是 bug**：tying 让
   `tok_embeddings.weight` 与 `lm_head.weight` 是同一个 tensor，
   而 PP 把 embedding 放在 stage 0、lm_head 放在末 stage，一个 tensor 不能在两个 stage。
2. **TP 上限 = 2** —— `tensor_parallel_degree (4) must divide n_kv_heads (2)`。
   Qwen3.5-0.8B 只有 2 个 KV head，任何 rank 数下 tp 都不能 >2。
3. **TP × FSDP 有 stride bug** —— tp2 × dp_shard2 报
   `view size is not compatible with input tensor's size and stride`。**未解决**。

### `--dry-run` 不能验证多 rank（重要，别被误导）

`fake_backend` **不做任何通信**，后果分两类：

- **PP 必然死**：stage 初始化要用 P2P 交换形状元数据（`_recv_meta`），
  收不到就是垃圾形状 —— 实测 `tried to allocate 4517329193108106637 bytes`
  或 `_pickle.UnpicklingError: invalid load key`。
- **TP / FSDP / HSDP 报 `nan`**：all-reduce / all-gather 是 no-op，
  数值本来就没意义 —— `Loss is not finite (global_avg_loss=nan) at step 2`。

⇒ `--dry-run` 只能用来确认「配置能解析、mesh 能建起来」。
数值相关、以及**任何 PP，都必须真跑**。

顺带修了一个 bug：`--dry-run` 没给子进程设 `NGPU`，而 torchtitan 从 `NGPU`
（不是 `WORLD_SIZE`）读 mesh 的 world size ⇒ 任何 `-n > 1` 的干跑都报
`NGPU environment variable must be set`。已修。

### 维度排序（按每步通信量，从便宜到贵）

| 维度 | 每步传什么 | 是否分片 参数/梯度/Adam |
|---|---|---|
| **PP** | stage 边界激活（P2P） | ✅ 1/pp，且**没有全量 all-gather 缓冲** |
| **TP** | 每层激活 all-reduce | ✅ 1/tp |
| **FSDP** | **全量参数 all-gather + 梯度 reduce-scatter** | ✅ 分片，但**每 rank 固定 ~4.8 GiB 瞬态缓冲，不随 rank 数缩小** |

⇒ 内存模型对比（bf16）：
```
纯 FSDP N rank：6.83 GiB + 4.8 GiB × N     → N=4: 26 GiB（本机放不下）
PP=4, dp_shard=1：每 rank 6.83/4 + ~0.5    → 合计 ~8.8 GiB
```

**CPU 上并行的目的只有「装得下」，不是「跑得快」** —— 2 rank 实测 140 s/step
比 1 rank 的 64 s/step **慢 2.2 倍**，瓶颈是 gloo over TCP 每次 all-gather 搬
1.71 GiB。别用加速比评估，用「能不能跑完」评估。

### 本次改动（commit `aba408f40`）

- `convert_qwen35_hf.py` 加 **`--untied`**：把 `lm_head.weight` 从 embedding
  复制一份写进 DCP（这正是 tying 在运行期做的事，只是落盘了）。
  实现要点：`to_hf` 后**先删掉** `lm_head.weight` 再做 coverage 与 `dcp.load`
  （磁盘上没有这个键，不删会加载失败），load 完再 `clone()` 回来。
  代价：852,985,920 → ~1.107B 参数，bf16 状态 6.83 → ~8.85 GiB。
- 新增配置 **`qwen35_0_8b_pp_bf16`**：`weight_tying=False`（PP 强制）
  + `local_batch_size=4`（batch 1 时 PP 只有 1 个 microbatch ⇒ 流水线完全串行，
  白白多付 P2P 开销）。
- `run_cpu_train.py`：干跑时给子进程设 `NGPU`。
- `cpu_lab/README.md` 新增「Hybrid parallelism on this host」章节：
  三约束表 + 维度成本表 + 两个内存模型 + 四条可直接跑的 recipe。
