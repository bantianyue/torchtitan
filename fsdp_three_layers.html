1. 第 1 层 · 用户层：FSDP 不需要写分片

🧩 和 TP/EP 最大的不同 TP/EP 需要在 models/<模型名>/sharding.py 里逐个权重写 ShardingConfig； FSDP 完全不需要——它不关心"哪个参数怎么切"，它只关心"把整层的所有参数沿 DP 网格切一份"。 所以用户层没有 per-param 声明，只有两道开关。

用户要配的只有 ParallelismConfig（配置里）和模型入口里的一次函数调用。真正能由用户拨动的开关有 3 个，都从配置字段流进 apply_fsdp_to_decoder 的对应形参：

# ① 配置文件（ParallelismConfig / TrainingConfig）—— 用户能拨动的 3 个开关
enable_symm_mem  = parallelism.enable_fsdp_symm_mem        # → enable_symm_mem
cpu_offload      = training.enable_cpu_offload            # → cpu_offload
fsdp_reshard_after_forward = parallelism.fsdp_reshard_after_forward  # → reshard_after_forward_policy

# ② models/deepseek_v3/parallelize.py —— 把 3 个开关传给第 2 层函数
apply_fsdp_to_mtp_decoder(
    model, dp_mesh,
    param_dtype=..., reduce_dtype=...,
    cpu_offload=training.enable_cpu_offload,
    reshard_after_forward_policy=parallelism.fsdp_reshard_after_forward,
    enable_symm_mem=parallelism.enable_fsdp_symm_mem,
    ep_degree=parallel_dims.ep, edp_mesh=edp_mesh,
)

结论：FSDP 的用户层没有 per-param 分片配置，只有"3 个开关 + 1 次调用"。 轴（网格）也不是用户写的——见下一层，由 resolve_fsdp_mesh 从 parallel_dims 推出。

1.1 这 3 个参数：用户到底控制了什么

参数用户配置字段功能用途内部实现
reshard_after_forward_policy fsdp_reshard_after_forward 权衡显存 vs 通信。控制前向之后是否立刻把参数重新切回 1/DP（释放全量副本）。
"always"=每次都 reshard（最省显存，但每次前向都要 all-gather）；
"never"=从不 reshard（显存常驻，前向免通信，但占用大）；
"default"=无 PP 时 reshard，有 PP 时不 reshard。		 get_fsdp_reshard_after_forward_policy()（fsdp.py:54-79）把字符串解析成布尔，传给 fully_shard(..., reshard_after_forward=)
cpu_offload enable_cpu_offload 用 CPU 内存换 GPU 显存。让模型参数驻留在 CPU 内存，前向时再搬到 GPU 参与计算。
面向超大模型显存不够的场景——代价是每次前向/反向都有 GPU↔CPU 搬运。		 if cpu_offload: fsdp_config["offload_policy"]=CPUOffloadPolicy()（fsdp.py:173-174），插进 fully_shard 配置
enable_symm_mem enable_fsdp_symm_mem 优化通信带宽/延迟。启用 PyTorch 的对称内存（SymmetricMemory）通信：为 all-gather / reduce-scatter 分配对称缓冲，减少 host 拷贝、提高聚合通信效率。
面向通信瓶颈场景，是纯性能优化、不影响语义。		 enable_fsdp_symm_mem(model)（fsdp.py:44-52）：遍历 FSDPModule， 调 set_force_sum_reduction_for_comms(True) + set_symm_mem_for_comm()
💡 三者一句话记住 reshard_after_forward = 省显存还是免通信（默认按有无 PP 智能取舍）； cpu_offload = 把参数放 CPU 换 GPU 显存（默认关）； enable_symm_mem = 通信性能优化（默认关，纯提效不影响结果）。
前两个影响"显存"，第三个只影响"通信速度"。

2. 第 2 层 · Titan 层：apply_fsdp_to_decoder

2.1 先解析出 FSDP 网格（full_dtensor.py:70-106）

用户没写网格，Titan 从 parallel_dims 里算出 dense storage mesh，并告诉 FSDP"哪些轴是数据并行轴"：

def resolve_fsdp_mesh(parallel_dims) -> (DeviceMesh, DataParallelMeshDims):
    storage_mesh = parallel_dims.get_activated_mesh(["dp_replicate", "dp_shard", "cp", "tp"])
    # 真实值（本例）：storage_mesh = (dp_replicate=2, dp_shard=8, cp=1, tp=1)
    shard_axes = ["dp_shard"];  shard = "dp_shard"
    return storage_mesh, DataParallelMeshDims(shard=shard, replicate="dp_replicate")
#           ↑ 2 组 × 8 卡：replicate 轴"dp_replicate"(2 组)，shard 轴"dp_shard"(每组 8 卡)

2.2 逐层 fully_shard（fsdp.py:110-310）

for layer_id, transformer_block in model.layers.items():
    # 真实值：transformer_block = layers.{layer_id}（一个完整的 decoder 层）
    fsdp_config = { "mesh": dp_mesh, "mp_policy": mp_policy,
                    "dp_mesh_dims": dp_mesh_dims }   # dp_mesh_dims(shard="dp_shard", replicate="dp_replicate")
    reshard_after_forward = get_fsdp_reshard_after_forward_policy(

    #       "default" + 有PP → False（避免每个 microbatch 都 all-gather）

    if getattr(transformer_block, "moe_enabled", False):
        # MoE 层：用 shard_placement_fn 把"专家权重"和"其他权重"分配到不同 mesh
        ...
    else:
        fully_shard(transformer_block, **fsdp_config, reshard_after_forward=reshard_after_forward)
    # 真实值：60 层各调用一次 fully_shard，每次把该层所有参数沿 dp_shard 轴切分

fully_shard(model, **fsdp_config)   # 最后整模型兜底
disable_fsdp_gradient_division(model)   # 关闭 FSDP 自动梯度均分，用全局 token 数自己算
if "dp_replicate" in (dp_mesh.mesh_dim_names or ()):
    logger.info("Applied HSDP to the model")   # 有 replicate 轴 → HSDP

注意加了一个转折：FSDP 的"切"发生在每层内部。以 layers.0.attention.wo.weight（(24576, 24576)）为例， Titan 不会为它写分片配置，而是把它整层交给 fully_shard，由 FSDP2 自己决定沿 dp_shard 轴切第 0 维。

2.3 MoE 层到底特殊在哪（关键点 1）

⚠️ 问题：MoE 层不是"一个整体"可以按同一把刀切 一个 MoE Transformer 层里有两类来源不同、角色不同的参数： 普通参数（attention、norm、router、shared experts 的 w1/w2/w3）和 路由专家权重（inner_experts 的 w1/w2/w3 GroupedExperts）。 这两类要么走不同的 FSDP 网格，要么走不同的切分维度——这就是 MoE 层在 FSDP 里必须特判的原因。 
# fsdp.py:216-308 —— 每个 MoE 层单独处理
if getattr(transformer_block, "moe_enabled", False):
    experts = transformer_block.moe.routed_experts.inner_experts   # GroupedExperts
    expert_params = set(experts.parameters())   # 专家权重集合（区别于普通参数）
    num_experts = experts.num_experts                            # 160

    # ① 决定专家权重沿哪个维度切（关键：Shard(0) vs Shard(1)）
    if ep_degree > 1:
        efsdp_ep_size = edp_mesh["efsdp"].size() * ep_degree   # 专家权重的数据并行规模
    else:
        efsdp_ep_size = fsdp_config["mesh"].size()
    if efsdp_ep_size > num_experts:
        expert_shard_placement = Shard(1)   # 卡数 > 专家数 → 切专家内部维，避免空 shard/padding
    else:
        expert_shard_placement = Shard(0)   # 否则沿专家维切（EP 的经典做法）

    # ② 按 ep_degree 选不同策略
    if ep_degree == 1 and expert_shard_placement == Shard(0):
        fully_shard(transformer_block, **fsdp_config, ...)      # 最简：整层一刀切
    elif ep_degree == 1:
        def _experts_shard_placement_fn(param, _expert_params=expert_params):
            return Shard(1) if param in _expert_params else None   # 只把专家权重切 dim1
        fully_shard(transformer_block, ..., shard_placement_fn=_experts_shard_placement_fn)
    else:   # ep_degree > 1：专家权重分到稀疏 mesh（edp_mesh），其它参数分到普通 dp_mesh
        def _shard_placement_fn(param, ...):
            if param in expert_params:
                return ShardPlacementResult(placement=_expert_placement, mesh_info=_edp_mesh_info) # → 稀疏 mesh
            else:
                return ShardPlacementResult(placement=Shard(0), mesh_info=_dp_mesh_info) # → 稠密 mesh
        fully_shard(transformer_block, ..., shard_placement_fn=_shard_placement_fn)
情形专家权重切法解决的问题
EP=1，且卡数 ≤ 专家数和整层一起，普通 Shard(0)最简单，不需要特判
EP=1，但卡数 > 专家数专家权重 Shard(1)，其它参数照旧避免专家维切不完导致某些卡拿到空 shard（padding 浪费）
EP > 1专家权重 → 稀疏 mesh (dp_replicate, efsdp, ep)；其它参数 → 稠密 mesh专家权重要走 EP 的 all-to-all，必须在 ep/efsdp 轴上单独分，不能和普通参数混在 dp_mesh 上
💡 一句话：MoE 特判解决什么 MoE 层里有一块"按专家切"的参数（路由专家）和一块"普通切"的参数（其余）。 两者角色不同，shard_placement_fn 就是"按参数名/归属，逐个决定用哪个 mesh、切哪个维"的钩子—— 这样专家权重跟 EP 走、其它参数跟普通 FSDP 走，互不干扰。

2.4 显式 prefetch（EP 启用时的通信重叠优化）

FSDP 默认有隐式 prefetch：根据运行时模块执行顺序提前预判"下一层要 all-gather 哪些参数"，把通信和前向计算重叠。 但 EP 启用时 token 的 D2H 同步会打乱这个预判，导致隐式 prefetch 失效。

# fsdp.py:326-366 —— 仅 EP 启用时（ep_degree > 1）走显式 prefetch
if ep_degree == 1:
    return   # EP 关：交给 FSDP 隐式 prefetch，不需要手动

# 前向：每层提前声明"我要预取下一层的参数"
transformer_blocks = list(model.layers.values())
next = transformer_blocks[1:] + [None]
for block, nblock in zip(transformer_blocks, next):
    if nblock is not None:
        block.set_modules_to_forward_prefetch([nblock])     # 前向预取下一层参数
    elif model.norm is not None:
        block.set_modules_to_forward_prefetch([model.norm, model.lm_head])

# 反向：同理，从后往前预取
reversed_blocks = list(reversed(model.layers.values()))
prev = reversed_blocks[1:] + [None]
for block, pblock in zip(reversed_blocks, prev):
    if pblock is not None:
        block.set_modules_to_backward_prefetch([pblock])
⚙️ 显式 prefetch vs 隐式 prefetch 隐式（EP 关）：FSDP 靠运行时顺序自己猜下一层，自动预取——无需用户管，但对 D2H 同步敏感。
显式（EP 开）：torchtitan 用 set_modules_to_forward_prefetch / set_modules_to_backward_prefetch 把"下一层是谁"显式写死，让 all-gather 稳定地与计算重叠，免受 EP 的 host 同步干扰。
这是 FSDP + EP 组合下特有的性能修补，普通 FSDP 或非 EP 的 MoE 不需要。

3. 第 3 层 · Torch 层：fully_shard 的物理动作

PyTorch 的 torch.distributed.fsdp.fully_shard（FSDP2 可组合 API）收到一个 nn.Module 和一个 DeviceMesh，做三件事：切参数、前向 all-gather、反向 reduce-scatter。

# 以 tok_embeddings.weight (102400, 5120) 为例，dp_shard 组内 8 卡：
# ① 参数切分（注册时）
fully_shard(model.tok_embeddings, mesh=dp_mesh, dp_mesh_dims=DataParallelMeshDims(shard="dp_shard"))
#    → weight 变成 DTensor，placements = (Shard(0) 于 dp_shard, Replicate 于 dp_replicate)
#    → 每卡全局形状 (102400, 5120)，每卡局部 (102400/8, 5120) = (12800, 5120)

# ② 前向：参数全量 all-gather
#    每卡把 1/8 的参数片段广播给组内 8 卡（AllGather），临时合成完整 (102400, 5120) 参与 matmul
#    真实值：每次前向触发 8 卡 AllGather，每卡 12800×5120 的 shard → 全局 102400×5120

# ③ 反向：梯度 reduce-scatter
#    每卡算出自己那段的梯度后，做 ReduceScatter 把 8 卡梯度求和并按段切回
#    → 每卡持有 (12800, 5120) 的完整梯度 shard
⚙️ FSDP vs TP 通信的本质区别 TP 把计算维度切了——每卡只算一部分特征，卡间靠 matmul 的并行自然协作； FSDP 把参数本身切了——每卡只存 1/DP 的参数，但每张卡都要算完整的数据， 所以靠"前向 all-gather 参数 + 反向 reduce-scatter 梯度"来交换。
FSDP 从不关心权重是 colwise 还是 rowwise——它只按数据并行轴切第 0 维，是"最笨但最通用"的切分。

4. 全链路流转 + 真实值汇总

1
用户3 个开关：fsdp_reshard_after_forward、enable_cpu_offload、enable_fsdp_symm_mem；调用一次 apply_fsdp_to_mtp_decoder。无 per-param 分片。
2
Titan算网格：resolve_fsdp_mesh 从 parallel_dims 得到 storage mesh (dp_replicate=2, dp_shard=8, cp=1, tp=1) + DSDP 轴声明。
3
Titan逐层 shard：apply_fsdp_to_decoder 对 60 层每层调 fully_shard；MoE 层用 shard_placement_fn 单独处理专家权重。
4
Titan（MoE+EP）显式 prefetch：EP 启用时用 set_modules_to_forward/backward_prefetch 把前向/反向预取下一层写死（绕过隐式 prefetch 的 D2H 干扰）。
5
Torch切参数：每层参数沿 dp_shard 轴切成 Shard(0)，每卡只存 1/8。
6
Torch前向 AllGather：每步前向，把 8 卡参数片段拼回完整权重再计算。
7
Torch反向 ReduceScatter：梯度求和并切回，每卡拿到自己参数 shard 的完整梯度。
