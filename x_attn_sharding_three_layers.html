0.1 张量形状约定

符号形状含义
x_BLD(B, L, D)激活：B=batch，L=序列长度，D=隐藏维
q/k/v_BLNH(B, L, N, H)注意力内部：N=头数，H=每头维度（此时 N×H = D）
weight（Linear）(out, in)PyTorch Linear 权重形状，dim 0 = 输出维，dim 1 = 输入维

0.2 网格轴（DeviceMesh 维度）

轴全称在激活上的作用
DPData Parallel（full_dtensor 下展开为 dp_replicate + dp_shard）切 batch 维（S(0)）
CPContext Parallel切序列维（S(1)）
TPTensor Parallel切序列维（SP 下）或切隐藏维（权重）

0.3 spmd 类型符号（本仓库统一用 spmd_types 的记号）

符号含义映射到 DTensor placement
spmd.RReplicate：每卡持有完整副本Replicate()
spmd.IInvariant：数据上等价于 R，但反向无梯度规约语义（"本就一样，无需管"）Replicate()
spmd.VVarying：随 partition_spec 决定切在哪一维由 partition_spec 转成 Shard(d)
spmd.S(d)Shard：按张量第 d 维切分Shard(d)
spmd.PPartial：各卡持有局部和，消费前需规约Partial()
🔑 记忆口诀 V + partition_spec 是"把切分写在张量维度上"的写法； S(d) 是"把切分写在网格轴上"的写法。两者最终都换算成 DTensor 的 Shard(d)。

0.4 三层各干什么（一句话版）

用户层 · 声明
往每个模块的 sharding_config 里填 ShardingConfig： 激活用 in_src / in_dst_shardings，权重用 state_shardings。 不产生任何通信。
Titan 层 · 编排
Module.parallelize() 扫描配置：参数/缓存调 distribute_tensor 建 DTensor； 重写 forward，在算子执行前按 in_src→in_dst 调 redistribute， 执行后按 out_src→out_dst 再调一次。
Torch 层 · 执行
DTensor.redistribute 内部把布局差异翻译成 NCCL 集体通信内核 （all-gather / all-reduce / reduce-scatter / shard），并维护反向传播的伴随算子。

1. 激活 x：怎么布局、怎么切分、怎么聚合

以 MLA attention 的输入边界为例（torchtitan/models/deepseek_v3/sharding.py:98-105）：

# deepseek_v3/sharding.py —— attention 模块的 ShardingConfig
attention.sharding_config = ShardingConfig(
    in_src_shardings={ "x": attn_x_layout },                # 进入前：SP 布局（序列被切）
    in_dst_shardings={ "x": dense_activation_placement(tp=spmd.R) },  # 进入后：TP 上聚合为 Replicate
)

其中 attn_x_layout 由 enable_sp（Sequence Parallelism）开关决定（同文件 90-94 行）：

attn_x_layout = (
    dense_sequence_parallel_placement()          # enable_sp=True ：x 在层间是序列切分的
    if enable_sp
    else dense_activation_placement(tp=spmd.I)  # enable_sp=False：x 在 TP 上不切（I≈R）
)

1.1 用户层：x 的布局长什么样

两个布局函数定义在 torchtitan/models/common/decoder_sharding.py：

# decoder_sharding.py:34-50  —— 通用激活布局：DP 切 batch，CP 切序列，TP 由调用方指定
def dense_activation_placement(*, tp, cp=spmd.S(1)) -> SpmdLayout:
    return SpmdLayout({ DP: spmd.S(0), CP: cp, TP: tp })

# decoder_sharding.py:53-62  —— 序列并行（SP）激活布局：batch/seq 分给 DP/CP/TP
def dense_sequence_parallel_placement() -> SpmdLayout:
    return SpmdLayout(
        { DP: spmd.V, CP: spmd.V, TP: spmd.V },
        partition_spec=(DP, (CP, TP), None),   # 张量 (B, L, D)：dim0→DP，dim1→CP+TP，dim2 不切
    )
📐 换算结果（对 x_BLD = (B, L, D)）
dense_sequence_parallel_placement() → DP: S(0)，CP: S(1)，TP: S(1)（batch 归 DP，序列长度同时被 CP 和 TP 切）
dense_activation_placement(tp=spmd.R) → DP: S(0)，CP: S(1)，TP: R（序列只在 CP 上切，TP 上是完整副本）

所以 attention 输入边界的布局变化是：

模式in_src（进入前，attn_x_layout）in_dst（进入后）需要的通信
SP 开（enable_sp=True） DP:S(0) CP:S(1) TP:S(1) DP:S(0) CP:S(1) TP:R TP 轴 all-gather（序列段聚合）
SP 关（enable_sp=False） DP:S(0) CP:S(1) TP:I（≈R） DP:S(0) CP:S(1) TP:R 无（I 与 R 在 DTensor 层都是 Replicate）

1.2 Titan 层：x 的重分布编排

Module.parallelize()（torchtitan/protocols/module.py:248-294）对每个带 _sharding_config 的模块：

# module.py:289-294 —— 重写 forward：执行前对齐输入，执行后对齐输出
def forward_with_redistribution(*args, **kwargs):
    args, kwargs = self._redistribute_inputs(parallel_dims, args, kwargs)   # 边界 A：in_src → in_dst
    outputs = fn(*args, **kwargs)
    return self._redistribute_outputs(parallel_dims, outputs)           # 边界 B：out_src → out_dst

self.forward = forward_with_redistribution

对 x 的完整处理流程（_redistribute_inputs，module.py:518-629）：

1
Titan提升 / 校验（in_src）
读 value.placements。若 x 是普通 Tensor（数据入口处）： full_dtensor 后端下直接 raise "Got a plain Tensor"（module.py:593-597）—— 因为输入早在 trainer 里被 parallelize_inputs 包装过了（见下）； 其他后端则用 in_src_shardings 调 DTensor.from_local 提升（module.py:599-606）。
若已是 DTensor：校验其 placements 必须与 in_src_shardings 一致（module.py:608-617，不一致 raise）。
2
Titan比对（in_dst）
解析 in_dst_shardings["x"] = {DP:S(0), CP:S(1), TP:R}，用 check_dtensor_placements_match 与当前 placements 比对（module.py:619-623）。
3
Titan发起重分布
发现 TP:S(1) ≠ TP:R，调用 value.redistribute(placements=desired, async_op=True)（module.py:624）。 只发出"指令"，不执行通信。
4
Torch物理执行
redistribute 内部推导出 S(1)→R = all-gather，在 TP 组上发 NCCL all_gather_into_tensor，把各卡 (B, L/TP, D) 的序列段拼成 (B, L, D) 完整副本。
🌱 x 的 DTensor 是哪里建的？
数据入口（每个 step 一次）：trainer.py:716-719 → full_dtensor.parallelize_inputs（full_dtensor.py:128-167）， 按 DP→Shard(0)、CP→Shard(1)、TP→Replicate 用 DTensor.from_local 包装输入/labels。
层间流动：上一层（如 norm）输出天然是 DTensor —— 由第 3 层 DTensor 算子（matmul 等）自动产出。 所以 attention 拿到 x 时几乎总是 DTensor，模块钩子里的 from_local 提升主要是给 非 full_dtensor 后端的兜底。

1.3 Torch 层：all-gather 长什么样

以 TP=2（卡 0、卡 1），SP 开为例，x_BLD 在 attention 边界前被序列切分，进入时被聚合：

进入前（in_src，每卡局部）：
卡0：seq 0..3
卡1：seq 4..7
 
⬇ NCCL AllGather（TP 组） ⬇
进入后（in_dst，每卡完整）：
seq 0..7
seq 0..7

DTensor 的通信推导规则（对 x_BLD 的每个网格轴独立判断）：

src placementdst placementPyTorch 内部动作
Shard(1)（TP 轴）ReplicateAllGather：每卡广播自己的序列段并拼接
ReplicateShard(1)Shard：本地切片（无通信，或仅数据搬运）
Shard(0)（DP 轴，batch）Shard(0)不变，不通信
Shard(1)（CP 轴）Shard(1)不变，不通信（CP 的序列切分保留）

注意 attention 模块的 in_dst 只把 TP 轴聚合：DP/CP 的切分原样保留 —— 所以注意力是在 "batch 切成 DP、序列切成 CP、TP 每卡都有完整序列"的布局下计算的。

2. Attention（MLA）矩阵：每块权重怎么声明、怎么切

DeepSeek-V3 的 MLA 注意力（torchtitan/models/deepseek_v3/model.py 的 Attention）权重结构： 低秩投影 wkv_a / wq_a、上投影 wkv_b / wq_b（或直连 wq）、输出投影 wo、 两个 RMSNorm（kv_norm / q_norm）与 RoPE 缓存。全部在 _set_deepseek_v3_layer_sharding （sharding.py:72-151）里声明：

# deepseek_v3/sharding.py:98-133 —— MLA 各子模块的 ShardingConfig
attention.sharding_config = ShardingConfig(          # 边界：x 的聚合（第 1 节已讲）
    in_src_shardings={ "x": attn_x_layout },
    in_dst_shardings={ "x": dense_activation_placement(tp=spmd.R) },
)
attention.rope.sharding_config = ShardingConfig(
    state_shardings={ "cache": dense_param_placement(tp=spmd.R) },  # RoPE 缓存：R@TP
)
replicate_weight = ShardingConfig(                   # 低秩/逐元素算子：权重不切
    state_shardings={ "weight": dense_param_placement(tp=spmd.R) },
)
attention.wkv_a.sharding_config = replicate_weight    # 低秩投影 (kv_lora_rank+qk_rope, D)  → R
attention.kv_norm.sharding_config = replicate_weight  # 逐元素 RMSNorm                        → R

attention.wkv_b.sharding_config = colwise_config()    # 上投影 (D, kv_lora_rank)              → S(0)
attention.wo.sharding_config = rowwise_config(output_sp=enable_sp)  # 输出 (D, D) → S(1)

set_gqa_inner_attention_local_map(attention.inner_attention)        # 内部 kernel：local_map + 头切分

if attention.q_lora_rank == 0:
    attention.wq.sharding_config = colwise_config()   # 无低秩：wq 直接 colwise S(0)
else:
    attention.wq_a.sharding_config = replicate_weight  # 低秩 q 投影 → R
    attention.q_norm.sharding_config = replicate_weight
    attention.wq_b.sharding_config = colwise_config()  # 上投影 → S(0)

两个"切分模板"定义在 decoder_sharding.py（注意：当前工作树删除了 colwise_config 定义， 以下为 git HEAD 版本）：

# decoder_sharding.py —— 列并行模板：切输出维
def colwise_config() -> ShardingConfig:
    return ShardingConfig(
        state_shardings={
            "weight": dense_param_placement(tp=spmd.S(0)),   # (out, in) 切 dim0 = 输出维
            "bias":   dense_param_placement(tp=spmd.S(0)),
        },
        out_src_shardings=dense_activation_placement(tp=spmd.S(-1)), # 输出切最后一维（out 特征）
    )

# decoder_sharding.py —— 行并行模板：切输入维，输出 Partial，再按需规约
def rowwise_config(*, output_sp: bool = False) -> ShardingConfig:
    out_dst = (
        dense_sequence_parallel_placement()      # SP 开：reduce-scatter 回序列分片
        if output_sp
        else dense_activation_placement(tp=spmd.I)  # SP 关：all-reduce 成完整
    )
    return ShardingConfig(
        state_shardings={
            "weight": dense_param_placement(tp=spmd.S(1)),   # (out, in) 切 dim1 = 输入维
            "bias":   dense_param_placement(tp=spmd.R),
        },
        out_src_shardings=dense_activation_placement(tp=spmd.P),   # 输出是 Partial（局部和）
        out_dst_shardings=out_dst,
    )

2.1 用户层：MLA 权重布局总表

权重形状 (out, in)声明TP 布局为什么
wkv_a(kv_lora_rank + qk_rope_dim, D)replicate_weightR输出是低秩小张量，复制成本低、省去后续通信
kv_norm / q_norm(dim,)replicate_weightRRMSNorm 是逐元素运算，切了反而要通信
wkv_b(D, kv_lora_rank)colwise_config()S(0)输出维切分：每卡算自己的输出切片，前向零通信
wq（q_lora_rank=0）(D, D)colwise_config()S(0)同 colwise
wq_a(q_lora_rank, D)replicate_weightR低秩
wq_b(D, q_lora_rank)colwise_config()S(0)上投影，输出维切分
wo(D, D)rowwise_config(output_sp=…)S(1)输入维切分：输出是 Partial，必须规约（这是 MLA 里唯一的通信点）
rope.cache(max_seq, dim)R@TPR每卡都需要完整缓存来算位置编码
🧩 为什么 MLA 这么切？
低秩投影（wkv_a / wq_a）复制：输出只有几百维，每卡复制一份的显存/计算成本远低于 为它做通信；上投影（wkv_b / wq_b / wq）colwise：输入 x 已被 gather 成 R@TP， R @ S(0) 的 matmul 输出天然按特征维切开，前向不需要任何通信； wo rowwise：它必须把各卡按头算出的部分和合并，是 attention 出口的"汇合点"， 顺便用 reduce-scatter 把输出还原成 SP 序列分片，供残差和下一层直接使用。

2.3 Torch 层：每个矩阵切的物理含义

distribute_tensor 把"每卡都有的全局权重"按 placements 切分/复制；redistribute 按 src/dst 推导通信。MLA 前向里 DTensor 的 matmul 布局规则（x 在 TP 上已是 R，即 x 的 TP placement 是 Replicate）：

算式布局结果通信
q = wq_b(norm(wq_a(x)))R @ S(0)ᵀS(-1)（输出特征切分）无（每卡独立算自己的输出切片）
kv = wkv_b(kv_norm(wkv_a(x)))R @ S(0)ᵀS(-1)无
inner attention（FlexAttention）q/k/v 头切分 S(2)；k/v 先 CP all-gatherattn 输出 S(2)CP 组 all-gather（k/v 各一次）
out = wo(attn)S(-1) @ S(1)ᵀPartial必须规约
规约（SP 开 / 关）P → SP 布局 / P → RS(1)@(CP,TP) / Rreduce-scatter / all-reduce
⚙️ 通信内核小结（按出现频率）
AllGather：① attention 入口把 x 的 TP 序列段聚合（SP 模式）；② inner attention 里把 k/v 在 CP 上聚合。
ReduceScatter：wo 输出 Partial → SP 序列分片（SP 模式，把通信和"切回序列并行"合并成一次）。
AllReduce：wo 输出 Partial → 完整（非 SP 模式）。
反向传播时每个集体通信都有伴随算子（all-gather 的伴随是 reduce-scatter，反之亦然）， DTensor 自动处理，torchtitan 和用户都不用写。

4. 全景：一个 Transformer 层内的布局流转

1
用户声明：在 set_deepseek_v3_sharding_config → _set_deepseek_v3_layer_sharding 里给 attention / norm / FFN / MoE 填 ShardingConfig。零通信。
2
Titan训练启动：parallelize_deepseekv3 → model.parallelize(parallel_dims)。所有权重按 state_shardings 调 distribute_tensor 变 DTensor；所有 forward 被重写（输入/输出边界）。
3
Titan每步数据入口：trainer 调 parallelize_inputs，用 DTensor.from_local 把 inputs/labels 包装成 DP:S(0), CP:S(1), TP:R 的 DTensor。
4
Titanattention 边界（_redistribute_inputs）：校验 x 的 placements == in_src（SP 布局），发现 ≠ in_dst（TP:R），调 redistribute。
5
TorchAllGather：TP 组上 x 从 S(1) → R。此刻每卡拥有完整序列的 x，可以算全部注意力。
6
TorchMLA 计算：R 权重（wkv_a/wq_a/norm）逐元素/低秩；colwise 权重（wkv_b/wq_b）R@S(0)ᵀ → S(-1) 零通信；inner attention 头切分 + k/v CP all-gather；wo → Partial。
7
TorchReduceScatter / AllReduce：wo 的 Partial 输出按 out_dst 规约（SP 开 reduce-scatter 回序列分片，SP 关 all-reduce）。
8
Titan下一层：残差相加后，FFN 的 norm 以 SP 布局为 in_src 直接消费；FFN 内部 w1/w3 colwise、w2 rowwise（decoder_sharding.py:223-241），模式与 attention 完全对称。

一句话串起来

🧭 谁是"谁"
用户写 What：in_src/in_dst/state_shardings 三张表，全是文本。
Titan 管 When/Where：启动时建权重 DTensor、包 forward；forward 前后比对布局、调 redistribute。
Torch 管 How：redistribute / distribute_tensor / from_local 内部推导并发射 all-gather / all-reduce / reduce-scatter 内核，并维护反向的伴随算子。
