实线为每 rank 峰值 commit（进程向系统预留的字节），虚线为峰值 RSS（实际驻留）。 两者都随参数量线性增长；直线在 0 参数处的截距就是每 rank 的固定开销 （python + torch + dataloader），在本文的尺寸区间里它由截距主导， 所以「能跑多大」首先取决于开了几个 rank，而不是模型本身多大。

3. 结论

  • 内存上限（commit 口径）：约 232M (0.23B) —— 系统 commit 预算决定。
  • 内存上限（驻留口径）：约 364M (0.36B) —— 物理 RAM 决定。
  • 两者取小：232M (0.23B) 是这套配置下能启动的上限；再大就要么分配不到内存，要么开始疯狂换页。

commit 那一栏不是常数：Windows 需要时会自动把 pagefile.sys 撑大， 本次实验期间 commit 上限就从 40.75 GiB 长到 43.88 GiB，能长多大取决于系统盘剩余空间 （实测 13.43 GiB）。 所以「commit 口径上限」是个会浮动的数；真正硬的是物理内存那一栏—— 超出它的部分只能在页面文件里来回倒，每步耗时会被换页吞掉。
