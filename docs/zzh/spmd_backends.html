SPMD 后端对比 · default / full_dtensor / spmd_types

三个后端本质上是 DTensor 发展的三个阶段,区别在于 mesh 轴如何折叠、CP 是否自动处理、类型检查在运行时还是编译期。配置开关 --parallelism.spmd_backend(configs.py:139),默认 "default"。

用的最多的是 default(legacy)后端——它是默认值(configs.py:139),所有模型的 parallelize 函数都优先支持它,最稳定,生产环境首选。full_dtensor 和 spmd_types 是较新的开发中功能,mesh 轴更精细但生态尚不完整。

0parallelize_deepseekv3 函数详解(6 步流程)

这是 DeepSeek-V3 的并行化入口,由 pipeline_llm 对每个 PP 子模型调用(pipeline_parallel.py:108-122)。它按顺序施加 TP/SP/CP 声明、异步 TP、激活检查点、torch.compile、FSDP+EP 双 mesh 分片。其中步骤 ① 和 ⑤ 的行为因 spmd 后端而异,其余步骤统一。

pipeline_parallel.py:64-140) 先对全模型做 PP 层切分,然后对每个 model_parts[i] 调用此函数。 即:先纵切(PP),再对每段横切(TP/SP/FSDP/EP)。

结论:用的最多的是 default 后端

原因:

  • 默认值:configs.py:139 的默认值就是 "default",用户不配置时就走它。
  • 最稳定:所有模型的 parallelize 函数(llama3/parallelize.py、deepseek_v3/parallelize.py 等)都优先支持 default 路径,生产环境验证最充分。
  • 生态最完整:CP/manual 包装、FSDP 手动 mesh 解析、纯 DTensor 运行时——这些老路虽然繁琐但经过最多测试。
  • 转换成本:full_dtensor 和 spmd_types 是较新的开发中功能,mesh 轴更精细但有部分组件(如某些 custom op)还在适配中。

如果你刚开始用 torchtitan 或做生产训练,选 default 不会有坑。如果你在开发新模型或优化通信,full_dtensor 提供更显式的 cp 轴;spmd_types 适合探索编译期类型安全。
