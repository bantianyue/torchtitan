DeviceMesh 到底是啥

用一个 8 卡的例子，把 ParallelDims.build_mesh() 建出来的每张子网格画给你看。

dp_replicate=2, dp_shard=2, cp=1, tp=2, pp=1, ep=1, world_size=8

先记住一件事：mesh 不是新硬件，就是把 world_size 个 rank 按不同方式分组。 build_mesh() 先建一张 1D 的 world 网格，再 unflatten（展开）成带名字的多维子网格。 同一个 rank，在不同子网格里属于不同的组 -> 于是它同时参与 TP 通信、FSDP 通信、loss all-reduce…… 各走各的进程组。

下面每张图都是同一批 8 个 rank (0..7)，只是按不同轴重新分组着色。这正是 unflatten 的本质：换一种"形状"看同一组设备。

4loss 网格 = batch x cp

loss_mesh = dataloading_mesh["batch","cp"]._flatten("loss")，即把 batch 和 cp 两个轴合并。 本例 cp=1，所以 loss 组 = batch 组。对 rank 0 就是 {0,2,4,6} - 这 4 个 rank 各算了一部分 loss，要做 all-reduce 求和。

为什么 loss 组 = DP + CP
batch（数据并行）和 cp（序列并行）都把"数据"切开了，每个 rank 只看到一部分样本/序列，loss 只是局部值，必须跨这些 rank 归约。 TP/PP 不切数据，所以不在 loss 组里。若 cp=2，loss 组会扩成 batch * cp 个 rank。

6代码怎么取子网格

# parallel_dims.py - 本例：8 卡
parallel_dims = ParallelDims(
    dp_replicate=2, dp_shard=2, cp=1, tp=2, pp=1, ep=1, world_size=8
)
parallel_dims.build_mesh()   # 惰性：首次 get_mesh 时才真正建

# 以下均以 rank 0 的视角，返回它所在的那张子网格：
parallel_dims.get_mesh("tp")            # -> DeviceMesh({0,1})        张量并行通信
parallel_dims.get_mesh("batch")         # -> DeviceMesh({0,2,4,6})    dataloader 分片
parallel_dims.get_optional_mesh("loss")  # -> DeviceMesh({0,2,4,6})    loss all-reduce
parallel_dims.get_mesh("fsdp")          # -> DeviceMesh({0,2})        FSDP all-gather/reduce-scatter
parallel_dims.get_optional_mesh("cp")    # -> None   (cp=1，禁用，不建进程组)
parallel_dims.get_optional_mesh("pp")    # -> None   (pp=1，禁用)
parallel_dims.get_optional_mesh("ep")    # -> None   (ep=1，禁用)

get_mesh 取不到就抛 ValueError；get_optional_mesh 取不到返回 None。 所以业务代码写成 if (mesh := parallel_dims.get_optional_mesh("cp")) is not None: 就能优雅处理"该并行没开"的情况。

fake backend - 为什么单机能模拟 32 卡
build_mesh() 对 size=1（或 efsdp 在 ep=1 时）的轴用 "fake" backend 覆盖 （unflatten_mesh 的 backend_override），不创建真实 NCCL 进程组。 这就是 NGPU=32 COMM_MODE=fake_backend ./run_train.sh 的原理：mesh 照建，通信全走 fake， 用来在没 GPU / 没 NCCL 的环境里校验配置和网格构建。
注意 fsdp 是例外 - 即使 size=1 也保留真 backend，好让 fully_shard() 能装 MixedPrecisionPolicy。
把 cp / pp / ep 也开起来会怎样
它们只是给 world 网格多 unflatten 出几个轴，乘积仍须 = world_size：
- cp=2：dataloadering 变 4 维 (pp,batch,cp,tp)，loss 组扩成 batch*cp；
- pp=2：多出 pp 轴，模型按 stage 切到不同 rank 组；
- ep>1：激活 sparse 网格 (pp,dp_replicate,efsdp,ep)，efsdp 改走真 backend，MoE 专家分片开始通信。
换配置只是换展开形状，rank 还是那批 rank。
