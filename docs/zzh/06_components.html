1. 数据加载 Dataloader

BaseDataLoader(Stateful, ABC, Configurable) 要求所有数据加载器实现 state_dict/load_state_dict（为断点续训）。具体实现 ParallelAwareDataloader 继承 torchdata.StatefulDataLoader，知道自己的 dp_rank / dp_world_size。

class ParallelAwareDataloader(StatefulDataLoader, BaseDataLoader):
    def __init__(self, dataset, dp_rank, dp_world_size, **kwargs):
        self.dp_world_size = dp_world_size
        self.dp_rank = dp_rank
        self._rank_id = f"dp_rank_{dp_rank}"
        super().__init__(dataset, **kwargs)

    def state_dict(self):
        return { self._rank_id: pickle.dumps(super().state_dict()),
                 "world_size": self.dp_world_size }
  • 状态按 dp_rank 分片存储，避免跨维度复制。
  • 加载时校验 dp_degree 前后一致（不支持 dataloader resharding）。
  • kwargs 合法性校验：num_workers=0 时自动剔除 persistent_workers / prefetch_factor。
为什么数据留在 CPU
batch_generator（见 02 §3.1）yield 出的 batch 是 CPU 张量，train_step 逐 microbatch 上 GPU。这样梯度累积期间显存更可控，且不浪费 H2D 带宽在还没用到的小批上。

1.1 数据流水线:从原始文本到张量批次

以 HuggingFaceTextDataset 为例(hf_datasets/text_datasets.py:73-170):

  1. 文本编码:_tokenizer.encode(sample_text, add_bos=True, add_eos=True)(:135-137),把原始文本转为 token id 列表。
  2. 流式打包:token 缓冲累加,满 seq_len+1 时截一段(:149-165),input = x[:-1],label = x[1:](错位预测)。
  3. 位置编号:每个 token 附带位置编号(per-document 从 0 开始),用于 RoPE(:146)。
  4. DP 分片:split_dataset_by_node(ds, dp_rank, dp_world_size)(:95),每 rank 只读自己的 1/8。
  5. batch 打包:StatefulDataLoader 按 batch_size=local_batch_size(:278)打包 → [4, 8192]。
  6. CP 切序列:trainer.py:668-676在 post_dataloading_process 中切 → [4, 2048]。
  7. PP 微批切分:pp_schedule.step 内部 _split_inputs(schedules.py:559-576)沿 batch 维切 → 4 x [1, 2048]。

数据流全程:文本 → token → [4,8192] → [4,2048](CP) → 4x[1,2048](PP 微批)。

2. 优化器容器 OptimizersContainer

一个 Trainer 可能用多种优化器（比如不同参数组用不同配置，或 PP 下每 rank 多 optimizer）。OptimizersContainer(Optimizer, Stateful, Configurable) 把多个 optimizer 包成一个对象，对外暴露 step()/zero_grad()/state_dict()。

# optimizer.py
def default_adamw(lr=8e-4, **kwargs):
    return OptimizersContainer.Config(
        param_groups=[ ParamGroupConfig(
            pattern=r".*",                       # 正则匹配 FQN，first-match-wins
            optimizer_name="AdamW",
            optimizer_kwargs={"lr": lr, "betas": (0.9,0.95),
                             "eps": 1e-8, "weight_decay": 0.1}) ])
  • 参数组：ParamGroupConfig(pattern, optimizer_name, optimizer_kwargs) 用正则按 FQN 分流；同一类型合并进一个 optimizer 实例。
  • 实现模式：fused / foreach / for-loop / fused_opt_states_bf16；fused_opt_states_bf16 用 pre-hook 把 Adam 状态建为 bf16，走融合 CUDA kernel 的混合精度路径。
  • 状态扁平化：state_dict() 返回 FQN 键的扁平 dict（用 checkpoint_utils），解决 PP 下多 stage 同 index 参数组碰撞问题。
MoE 负载均衡 hook
register_moe_load_balancing_hook 在优化器 step 前注册 pre-hook：跨 rank all-reduce 每个专家的 token 计数，按 load_balance_coeff · sign(mean - per_expert) 更新 expert bias，实现 aux-loss-free 负载均衡。

3. 学习率调度 LRSchedulersContainer（WSD）

同样把多个 LambdaLR 包成容器（每个 optimizer 一个）。调度是 LambdaLR 的纯函数：warmup → stable → decay。

def linear_warmup_stable_decay(current_step, warmup, stable, decay, lr_decay_type, min_lr_factor):
    if current_step < warmup:
        return current_step / warmup                 # 线性 warmup
    if current_step < warmup + stable:
        return 1.0                                   # 稳定段
    progress = (current_step - warmup - stable) / decay
    if   lr_decay_type == "linear": adj = 1 - progress
    elif lr_decay_type == "sqrt":   adj = 1 - math.sqrt(progress)
    elif lr_decay_type == "cosine": adj = 0.5*(1+math.cos(math.pi*progress))
    return min_lr_factor + (1 - min_lr_factor) * adj   # WSD：最底不破 min_lr
  • WSD（Warmup-Stable-Decay）：decay_ratio=None 时 decay 紧跟 warmup；设了 decay_ratio 则先稳定一段再衰减（与 total_steps 解耦，方便用更少步调试）。
  • 检查点极简：只存 last_epoch，加载时各 scheduler 从自己 optimizer 的 base_lrs 重算 lr —— 对混合优化器与 resharding 都正确。

4. 损失：CrossEntropy + ChunkedLossWrapper

BaseLoss 统一签名 (pred, labels, global_valid_tokens) → (scaled_loss, metrics)，内部 loss = fn(...) / global_valid_tokens（sum 归约再按全局 token 数归一化）。

4.1 词表并行交叉熵（loss-parallel CE）

cross_entropy_loss 支持 vocab 沿 TP 切分：每个 rank 只持有 V/tp 个类，前向用 3 次 TP all-reduce（max / sumexp / gather）做分布式 log-softmax，反向融合且零额外通信（_LossParallelCrossEntropy）。支持不均匀 vocab 切分与 IGNORE_INDEX。

# loss.py（spmd_types 词表并行）
if get_spmd_backend() == "spmd_types" and spmd_mesh_size("tp") > 1:
    return _LossParallelCrossEntropy.apply(pred.flatten(0,1).float(),
        labels.flatten(0,1), current_spmd_mesh().get_group("tp"),
        global_vocab_size)

4.2 分块损失 ChunkedLossWrapper（省显存）

大词表时，[B, L, V] 的 logits 峰值显存巨大。ChunkedLossWrapper 把 hidden states 沿序列维切成 N 段，逐 chunk 跑 lm_head + CE + backward，峰值从 O(B·L·V) 降到 O(B·L/N·V)：

1模型前向 _skip_lm_head=True　得到 hidden states [B, L, D]
2detach + 切 N 段　每段作为 leaf，准备累积 .grad
3关 lm_head 的 reshard　让权重跨 chunk 保持 unsharded，避免重复 all-gather
4逐 chunk　lm_head(chunk) → loss_fn → backward → 把 chunk grad 汇入 GradAccumulator
5汇回 Decoder　用自定义 autograd Function（_DecoderOutputGradientBackProp）把累积梯度作为 hidden_states 的梯度，autograd 自动穿过 decoder
为什么用自定义 autograd Function 而不是 hidden_states.backward()
_DecoderOutputGradientBackProp.backward 直接返回 accumulated_grad 作为 hidden_states 的梯度，让 autograd 在单次遍历里把梯度传回 decoder，避免「图被反向两次」的错误。

5. 检查点 CheckpointManager

基于 PyTorch DCP（torch.distributed.checkpoint），统一管理 model / optimizer / lr_scheduler / dataloader / train_state 的保存与加载。

  • ModelWrapper：把多个 model part（PP 下）的 state_dict 扁平合并成一个稳定存储的视图，供 DCP 读写。TP 下自动把分片张量 consolidate 成完整张量。
  • 保存时机：_should_save = 首步（若开启）/ 间隔命中 / 末步。last_save_model_only 在训练结束时只存模型（可 torch.load(..., weights_only=True) 直接读）。
  • 异步模式：
    模式行为
    disabled同步落盘，训练循环阻塞到写完
    async线程 + async_save；仅 GPU→CPU 搬运阻塞，之后后台写盘
    async_with_pinned_mem独立进程 + 预分配 pinned 共享内存；训练几乎零阻塞（<1s），但 CPU RAM 占用高
  • HF 互操作：initial_load_in_hf / last_save_in_hf 通过 state_dict_adapter 把权重在 torchtitan 原生格式与 HF safetensors 之间转换（含分片合并 consolidate_safetensors_files_on_every_rank）。
PP + 优化器状态碰撞
各 PP rank 的 optimizer 用 index-based param_group（rank0 的 group[0] 是 layers.0，rank1 的 group[0] 是 layers.1），直接保存会互相覆盖。解决方式是对 optimizer 做扁平化（FQN 键），保证所有 part 的 state 不冲突。这是 OptimizersContainer.state_dict 返回扁平 dict 的原因。
  • DCP 保存流程:checkpointer.save(step)(trainer.py:899-902)→ _save 收集 model_part/optimizer/scheduler/dataloader/train_state 的 state_dict → distributed.checkpoint.save 写入存储路径。
  • DCP 加载流程:checkpointer.load(step)(trainer.py:873)→ _load 从存储路径读 → distributed.checkpoint.load 恢复到各组件。支持从指定 step 恢复(config.checkpoint.load_step)。
  • TP 分片合并:state_dict_adapter 在保存时可以 consolidate_safetensors_files_on_every_rank 把 DTensor 分片合并为完整张量,方便 HF 格式加载。
  • DCP 限制:不支持 dataloader resharding(dp_degree 前后不一致时报错);optimizer 状态需扁平化(PP 下避免碰撞)。

6. 指标 MetricsProcessor

  • 聚合：仅当 should_log(step) 为真才聚合；跨 DP/CP 用 loss_mesh 做 all-reduce 求 global_avg_loss / global_max_loss / n_tokens_seen。
  • MFU：用 get_peak_flops(device) 与 num_flops_per_token（模型 get_nparams_and_flops 算出）估算模型算力利用率。
  • 输出：stdout（默认）、TensorBoard（enable_tensorboard）、以及结构化 structured_logger 的 Gantt/step_state（用于性能分析）。

local_avg_loss = loss * global_valid_tokens / local_valid_tokens

7. 验证器 Validator

Validator 在训练循环中被周期性调用(trainer.py:905-908),使用与训练相同的 loss 路径(forward-only),不产生梯度。

  • 使用训练 loss 函数:ChunkedLossWrapper 在验证时走requires_grad=False分支(loss.py:622),只做 forward 和 loss 计算,不触发 backward 和 GradAccumulator。
  • 验证频率:validator.freq 配置,在 trainer.py:905-908 检查 should_validate(step)。
  • DP/CP 归约:与训练相同,loss 在 loss_mesh 上 all-reduce。
