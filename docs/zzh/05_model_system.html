1. Decoder / TransformerBlock：共享骨架

所有自回归 decoder-only 模型继承 Decoder(BaseModel)（models/common/decoder.py），它提供统一的 __init__ / forward / init_states / get_attention_masks。每个 transformer block 继承 TransformerBlock(Module)。

class Decoder(BaseModel):
    def __init__(self, config):
        self.tok_embeddings = config.tok_embeddings.build()
        self.layers = ModuleDict()
        for i, layer_config in enumerate(config.layers):
            self.layers[str(i)] = layer_config.build()
        self.norm   = config.norm.build()
        self.lm_head = config.lm_head.build()
        if self.enable_weight_tying:
            self.tok_embeddings.weight = self.lm_head.weight   # 权重共享

    def forward(self, tokens, positions=None, attention_masks=None):
        h = self.tok_embeddings(tokens)
        for layer in self.layers.values():
            h = layer(h, attention_masks, positions)
        h = self.norm(h)
        if self._skip_lm_head:   # ChunkedLossWrapper 用：lm_head 在 loss 里逐 chunk 做
            return h
        return self.lm_head(h)
为什么 lm_head 可以在 forward 之外做
当使用 ChunkedLossWrapper（大词表省显存），_skip_lm_head=True 让 Decoder 返回 hidden states，由 loss 函数把序列切成 N 段、逐 chunk 跑 lm_head + CE + backward，再用自定义 autograd Function 把梯度汇回 Decoder。详见 06 §损失。

1.1 TransformerBlock 的 forward 约定

llama3 的 block（models/llama3/model.py）最简洁：

def forward(self, x, attention_masks, positions=None):
    h = x + self.attention(self.attention_norm(x), attention_masks, positions)
    out = h + self.feed_forward(self.ffn_norm(h))
    return out

Decoder.Config 要求每个 block 有 attention、feed_forward（或 moe）、两个 norm。所有模型 Variant（llama3/qwen3/deepseek_v3/gpt_oss/flux）都遵循此骨架，差异只在子模块配置。

注意：update_from_config 同时承担「把训练配置（seq_len/并行度）灌进模型」和「生成声明式 sharding 配置」两件事。后者就是下一节的核心。

3. 声明式切分 ShardingConfig ⭐

这是 torchtitan 最新、最值得理解的设计：切分不再写在 parallelize_fn 的命令式代码里，而是作为每个模块 Config 上的 sharding_config 数据声明（protocols/sharding.py）。

class ShardingConfig:
    state_shardings:  dict[str, SpmdLayout]          # 参数/buffer 怎么分（按名字）
    in_src_shardings: dict[str, SpmdLayout] | None  # 输入源 placement
    in_dst_shardings: dict[str, SpmdLayout] | None  # 输入重切分目标
    out_src_shardings: SpmdLayout | tuple | None   # 输出源 placement
    out_dst_shardings: SpmdLayout | None       # 输出重切分目标
    local_map: LocalMapConfig | None             # 是否用 local_map 包 forward

SpmdLayout 用 mesh axis 名标注每个张量维的 placement（spmd.S / R / V / P / I）。例：colwise 线性权重 {TP: Shard(0)}；attention 输出 reduce-scatter 到 {TP: Shard(1)}（SP）；MoE 包装输出 {TP: Partial()}。

3.1 llama3 的切分声明（sharding.py）

def set_llama3_sharding_config(config, *, enable_sp):
    set_decoder_sharding_config(config, enable_sp=enable_sp)   # tok_emb/norm/lm_head
    for layer_cfg in config.layers:
        _set_llama3_layer_sharding(layer_cfg, enable_sp=enable_sp)

def _set_llama3_layer_sharding(layer_cfg, *, enable_sp):
    norm = norm_config(enable_sp=enable_sp)              # SP: Shard(1) 激活; 否则 Replicate
    layer_cfg.attention_norm.sharding_config = norm
    layer_cfg.ffn_norm.sharding_config      = norm
    set_gqa_attention_sharding(layer_cfg.attention, enable_sp=enable_sp)
    set_gqa_inner_attention_local_map(layer_cfg.attention.inner_attention)
    set_dense_ffn_sharding(layer_cfg.feed_forward, enable_sp=enable_sp)
声明与运行时解耦
enable_sp 控制 SP 是否开启，但所有 placement 声明都无条件写入。真正生效哪些，取决于运行时 Module.parallelize() 拿到的 parallel_dims：未被启用的 mesh 轴（如 TP=1）的声明在并行化时被跳过。这意味着同一份模型代码能适配任意并行组合。

4. Module.parallelize()：声明 → DTensor

Module.parallelize(parallel_dims)（protocols/module.py）是声明式切分的落地引擎。它递归处理每个子模块：

1递归　先并行化所有 Module 子节点（穿过非 Module 包装器如 CheckpointWrapper）
2分发状态　_distribute_states：按 state_shardings 把每个 param/buffer 变 DTensor（distribute_tensor / spmd_distribute_tensor）
3缓存 forward 签名　_cache_pos_arg_names：记录 forward 的位置参数名，供重切分用
4包 forward　若有 local_map 则包一层局部张量计算区；否则直接 forward
5重切分包裹　self.forward = forward_with_redistribution：
args,kwargs = _redistribute_inputs(...) → fn(...) → _redistribute_outputs(...)
# module.py（节选）
def parallelize(self, parallel_dims):
    self._parallelized = True
    # 1) 递归子模块
    # 2) 分发状态
    self._distribute_states(parallel_dims)
    self._cache_pos_arg_names()
    fn = self._maybe_wrap_with_local_region(self.forward, parallel_dims)
    def forward_with_redistribution(*args, **kwargs):
        args, kwargs = self._redistribute_inputs(parallel_dims, args, kwargs)
        outputs = fn(*args, **kwargs)
        return self._redistribute_outputs(parallel_dims, outputs)
    self.forward = forward_with_redistribution
每个 Module 只能 parallelize 一次
parallelize() 开头检查 self._parallelized，重复调用会抛 ValueError。这是防止 DTensor placement 被重复应用导致静默错误。

4.1 状态分发如何按 mesh 解析

_distribute_states 对每个参数：

  • 从 state_shardings[name] 取 SpmdLayout；
  • axes = layout.axes() 得到涉及的 mesh 轴 → resolve_mesh(axes) 得到子网格；
  • resolve_placements(layout, mesh) 按 mesh 轴的顺序把 SpmdLayout 解析成 tuple[Placement]（每个启用轴都要声明，缺一个就报错）；
  • size-1 轴上的 Shard/Partial 会被归一为 Replicate（操作等价，但 DTensor 的 view/reshape 严格模式会区分）。

5. config_registry：把一切打包成 ModelSpec

以 llama3_8b 为例，它把「模型超参 + 并行函数 + 损失 + 优化器 + 数据」全部组装进一个 Trainer.Config：

def llama3_8b():
    model_spec = model_registry("8B")      # 返回含 parallelize_fn=pipeline_llm? 等的 ModelSpec
    return Trainer.Config(
        model_spec=model_spec,
        loss=ChunkedLossWrapper.Config(loss_fn=CrossEntropyLoss.Config(...)),
        optimizer=default_adamw(lr=3e-4),
        training=TrainingConfig(local_batch_size=1, seq_len=8192, steps=1000),
        dataloader=HuggingFaceTextDataLoader.Config(dataset="c4"),
        parallelism=ParallelismConfig(tensor_parallel_degree=8),
        ...
    )

对应到模型文件夹的标准结构（models/llama3/）：
