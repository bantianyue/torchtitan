训练流程全景 · 从初始化切分到每个 train_step

DeepSeek V3 671B · 192 GPU · TP=2 / SP=2 / CP=4 / PP=3 / EP=2 / FSDP=8(dp_shard)。MoE:3 个 dense 层 + 58 个 MoE 层、256 路由专家(top-8,sigmoid)。MLA 注意力用低秩 Q(wq_a+wq_b)。图为主:初始化做一次(切权重/分层/分片/切专家),train_step 每步重复(切数据/切激活/EP 路由/通信)。全程以 parallelize_deepseekv3 为准。

本页配置: DP=8 FSDP=32(dense 组) TP=2 SP=2 CP=4 PP=3 EP=2 efsdp=32(专家组) global_batch=64 · local_batch_size=4 · seq_len=4096 · pp微批=4(Interleaved1F1B)

0全貌:初始化做一次,训练每步重复

整条训练流水线分两个阶段:[静] 初始化把权重/层/专家/数据组织切分好(做一次,之后不再变);[动] train_step每步把新数据切成段、在切好的权重上算前向/反向(MoE 每层做 EP 路由)、更新参数(每步重复)。

图 0-1:训练流水线全貌。左=初始化(静态切分,1 次),右=train_step(动态数据流,每步重复)。

1初始化:各并行策略切了什么

模型在 meta device 上构建后,先由 pipeline_llm 按 PP 切成 3 个 stage,再对每个 stage 跑 parallelize_deepseekv3:CP 包 attention(必须在 parallelize 前)-> model.parallelize 声明 TP/EP/SP -> async TP -> AC -> compile -> FSDP(含专家 efsdp)。全部静态:切分结果在初始化时定型,训练中不变。

图 1-1:初始化切分全景。原始权重 -> TP 半切(MLA 列/行、低秩复制)-> EP 切 256 专家 -> PP 分 3 段 -> FSDP dense 1/32 / expert 1/32 分片;数据由 DP 切 8 份。全静态。

2train_step:每步做什么(一次优化步)

train_step 执行 config.training.steps 次(官方 671B 配置 10000)。每步内部:zero_grad -> 预取 2 轮数据并统计有效 token -> 2× forward_backward_step(每轮 4 个 PP 微批)-> clip -> optimizer.step。8 次 fwd/bwd = 2 轮 × 4 微批。

图 2-1:train_step 内部结构。①② 每步 1 次,② 内每轮 1 次 forward_backward_step,每轮 4 个 PP 微批各跑一次前向/反向。

4各并行策略在训练流程中的核心动作

以下按 parallelize_deepseekv3(+ 外层 pipeline_llm)的真实调用顺序列每个策略的核心动作--代码位置、shape 变化、通信原语。分两组:初始化[静]在 parallelize_deepseekv3 里做一次;train_step[动]每步重复。每个策略的完整代码位置索引见 parallelism_code_map.html。

图 4-0:parallelize_deepseekv3 初始化动作调用顺序。外层 pipeline_llm 先切 PP,再对每个 stage 依次跑 ①-⑥。①(CP 包装)必须早于 ②(parallelize)。

4.1 CP 包装 attention -- 初始化,在 parallelize 之前 初始化

核心动作(此前漏掉的关键一步): apply_cp_to_forward([block.attention.inner_attention for block in model.layers.values()], cp_mesh)。把每层 inner_attention.forward 替换成 CP 版本--必须在 model.parallelize() 之前调用,这样 CP 包装会被 parallelize 的 local_map 捕获,在本地张量上执行。

# parallelize.py:43-48 (default backend 分支)
if parallel_dims.cp_enabled:
    apply_cp_to_forward(
        [block.attention.inner_attention for block in model.layers.values()],
        parallel_dims.get_mesh("cp"),
    )

# context_parallel.py:57-78 (FlexAttention 分支,DeepSeek V3 用 attn_backend="flex" 走此路)
def cp_forward(q, k, v, **kwargs):
    k = k.contiguous(); v = v.contiguous()
    global_k, global_v = flex_cp_allgather(k, v, 1, pg_name)   # 运行时才 all-gather
    return orig_fn(q, global_k, global_v, **kwargs)
# SDPA 分支则把 q/k/v 包成 Shard(1) 的 DTensor,靠 dispatcher 处理(无需手动 all-gather)

为什么是"初始化"动作: 这里只是替换 forward 函数,不切数据、不通信;真正的 CP all-gather 发生在每步 attention 被调用时(见 4.9)。顺序约束: 若在 parallelize 之后才包装,CP 逻辑会跑到 local_map 边界外、拿到的是 DTensor 而非本地张量,导致出错。

4.2 model.parallelize -- TP/EP/SP 声明式切分 初始化

核心动作: model.parallelize(parallel_dims) 递归读取每个子模块的 ShardingConfig(在 sharding.py 里预先填好),对权重施加 TP/EP/SP 放置。default backend 下仅 tp_enabled or ep_enabled 时调用。

# deepseek_v3/sharding.py:111-126 (MLA 投影的 ShardingConfig)
attention.wkv_b.sharding_config = colwise_config()              # 权重 S(0) 切输出维(头)
attention.wo.sharding_config   = rowwise_config(output_sp=True) # 权重 S(1) 切输入维,输出 RS
attention.wkv_a.sharding_config = replicate_weight              # 低秩投影 Replicate(TP)
attention.wq_a.sharding_config = replicate_weight               # 671B 低秩 Q 下投影也复制
attention.wq_b.sharding_config = colwise_config()               # 671B 低秩 Q 上投影列并行
attention.inner_attention: set_gqa_inner_attention_local_map(...)  # attention 的 local_map

# moe_sharding.py:273-291 (路由专家:EP 启用走 sparse 族,EP 关闭走 dense TP 族)
if enable_ep:
    state_shardings = {name: expert_param_placement_sparse()}   # {EP: S(0)} 按 E 维切专家
else:
    state_shardings = {name: expert_param_placement_dense(tp_placement=...)}  # TP 切 expert 内维

切了什么: MLA 的 wkv_b/wq_b 列并行(切头)、wo 行并行,wkv_a/wq_a/gate 复制;dense FFN 与共享专家列/行并行;embed/lm_head 切 vocab;路由专家 EP 按 E 维切(256->128)。SP: 通过 local_map 的 redistribute 在进线性层前 all-gather 序列、出线性层后 reduce-scatter。通信: 初始化无通信(只声明放置);运行时通信由 local_map 触发(见 4.11)。

4.3 maybe_enable_async_tp -- 异步 TP 初始化

核心动作: maybe_enable_async_tp(parallelism, compile_config, tp_mesh)。tp_enabled 且 enable_async_tensor_parallel 时,设 torch._inductor.config._micro_pipeline_tp = True,让 TP 的 all-gather/reduce-scatter 与上一层的 matmul 计算重叠。前提: 必须开 compile.components=["model",...](需要编译图才能插入异步通信)。不改权重,只设 inductor 配置。

通信: 运行时 TP all-gather 被拆成微流水线与计算重叠(异步)。parallelize.py:52-53 · tensor_parallel.py:102-115。

4.4 SelectiveAC.apply -- 激活检查点 初始化

核心动作: ac_config.build(dump_folder=...).apply(model) 遍历 model.layers,逐 transformer_block 包 checkpoint_wrapper。DeepSeek V3 用 SelectiveAC:保存昂贵算子(SDPA/FlexAttention、linear、topk、all-to-all/reduce-scatter 等)的输出,其余重算;每第二个 mm 重算;router.gate 强制重算(保持 MoE 路由稳定)。

# activation_checkpoint.py:152-163
def apply(self, model):
    _disable_dynamo_lru_cache()           # 规避 SAC+PP+Flex 的 dynamo LRU 交互
    layers = model.get_submodule("layers")
    for layer_id, block in layers.named_children():
        block = self._wrap_block(block, base_fqn=f"layers.{layer_id}")
        layers.register_module(layer_id, block)

效果: 反向时重算部分激活以省显存。无通信。 parallelize.py:59-60。

4.5 apply_compile -- torch.compile 初始化

核心动作: apply_compile(model, compile_config) 对每个 TransformerBlock 调 torch.compile(backend=..., fullgraph=True)(块级编译,利用重复结构)。用 FlexAttention 且 backend 为 aot_eager 时,经 _maybe_regional_inductor_backend 把 flex 区域 scoop 到 inductor 子编译。注: DeepSeek V3 671B 官方配置默认 compile.components=["loss"](只编译 loss),"model" 不在其中 -> 此步对 671B 默认配置是 no-op;开 model 编译才会编译各块。

无通信。 parallelize.py:62-63 · compile.py:35-58。

4.6 apply_fsdp_to_decoder -- FSDP 分片(含 EP 专家 efsdp) 初始化

核心动作: apply_fsdp_to_decoder(model, dp_mesh, ..., ep_degree=2, edp_mesh=efsdp_mesh, ...)。逐模块 fully_shard:dense 参数(MLA、dense FFN、embed、共享专家)走 dp_mesh(fsdp 组 = dp_shard×cp = 32);路由专家参数走 edp_mesh(efsdp 组 = 32),靠 shard_placement_fn 按"参数是否属于 experts"分流到不同 mesh。

# fsdp.py:229-272 (ep_degree > 1:per-param mesh)
def _shard_placement_fn(param, ...):
    if param in _expert_params:
        return ShardPlacementResult(placement=_expert_placement, mesh_info=_edp_mesh_info)  # efsdp=32
    else:
        return ShardPlacementResult(placement=Shard(0),        mesh_info=_dp_mesh_info)      # fsdp=32
fully_shard(transformer_block, ..., shard_placement_fn=_shard_placement_fn)

# fsdp.py:296-336 (EP 启用时设显式 forward/backward 预取,避免 EP D2H 同步干扰隐式预取)
# fsdp.py:285-286 disable_fsdp_gradient_division(model) -> 梯度除法由 loss÷gvt 负责

通信(运行时): 前向 all-gather 拼回完整参数;反向 reduce-scatter 梯度回 dense 1/32 / expert 1/32。PP 下默认 reshard_after_forward=False(stage 开头一次 all-gather,不逐微批)。注: EP=2 时 efsdp=32 与 dense fsdp=32 同大小(EFSDP=fsdp×tp/ep=32×2/2)。parallelize.py:84-97 · fsdp.py:81-336。

4.7 pipeline_llm -- PP 切分(外层,先于 parallelize_deepseekv3) 初始化

核心动作: trainer 在调 parallelize_deepseekv3 之前,先调 model_spec.pipelining_fn = pipeline_llm:_pipeline_module_split / split_module 按 FQN 把 61 层切成 3 个 stage(21/20/20,首段含 embed + 3 dense 层),再对每个 model_part 分别调 parallelize_deepseekv3(即 4.1-4.6 对每个 stage 各跑一遍)。schedule 用 Interleaved1F1B。

# pipeline_parallel.py:96-119
stages, model_parts = _pipeline_module_split(model, pp_mesh, schedule, device, module_names_per_stage, ...)
for i, m in enumerate(model_parts):
    m = parallelize_fn(m, parallel_dims=..., training=..., ...)   # 每个 stage 各自 parallelize_deepseekv3
    model_parts[i] = m; stages[i].submod = m
pp_schedule = _build_pipeline_schedule(...)

无通信(切分本身): 只决定层归属;stage 间通信在运行时由 schedule 的 p2p 触发(见 4.12)。pipeline_parallel.py:64-140, 428-444 · trainer.py:371-396。

以下是 train_step 每步重复的动态动作:

4.8 CP 切序列 -- 数据预处理 train_step

核心动作: prepare_context_parallel_input -> cp_shard -> _context_parallel_shard(mesh, buffers, seq_dims, load_balancer),在 forward_backward_step -> post_dataloading_process 里、每个微批调用。

# trainer.py:668-676
inputs, labels, extra_kwargs = prepare_context_parallel_input(
    inputs, labels, extra_kwargs, cp_mesh, device, load_balancer_type)  # 默认 "headtail"
# shape: [4, 4096] -> [4, 1024] (每 cp rank 持 1/4 序列,headtail 负载均衡)

通信: 无(逻辑分片,attention 内才 all-gather K/V)。动态: 每步现切。context_parallel.py:114-271。

4.9 CP all-gather K/V -- attention 内 train_step

核心动作: 由 4.1 安装的 cp_forward 在每步 attention 被调用时执行:flex_cp_allgather(k, v, 1, pg_name) 跨 cp_mesh 收集 K/V 沿序列维拼接成全量,只算本地 Q 段的 attention。

# context_parallel.py:57-78 (DeepSeek V3 FlexAttention 分支)
global_k, global_v = flex_cp_allgather(k, v, 1, pg_name)
return orig_fn(q, global_k, global_v, **kwargs)

# shape: Q 本地 [1,1024,64,192] (只算本地段 query,64/128 头)
#        K/V 本地 [1,1024,64,128] -> all-gather -> [1,4096,64,128] (cp=4 块全量)
# 反向:每块 K/V 梯度在 cp 组上 reduce(求和)

通信: all-gather(K/V 4 块 -> 1 份全量)。动态: 每微批现 gather。

4.10 EP dispatch / combine -- MoE 路由 train_step

核心动作: 每个 MoE 层(58 个),router.gate(复制权重)算全部 256 路由分 -> top-8 -> AllToAllTokenDispatcher.dispatch 用 all_to_all_single 把 token 按 top-k 专家送到对应 EP rank -> 本地 128 个路由专家 + 1 个共享专家计算 -> combine 再 all-to-all 把结果送回原 rank。

# token_dispatcher.py:239-385 (AllToAllTokenDispatcher,默认 EP 通信后端)
return all_to_all_single(...)   # dispatch: token 按专家分组送到 EP rank
...
return all_to_all_single(...)   # combine: 结果送回原 token 所在 rank
# shape: x [1,512,7168](SP 粒度)-> MoE 边界 redistribute -> 路由 -> 本地专家算 -> combine -> [1,512,7168]

通信: 两次 all-to-all(dispatch + combine),跨 ep_mesh(2)。动态: 每微批每 MoE 层。注: 也可选 hybridep/minimal_async_ep 后端(DeepEP)。

4.11 TP all-gather / reduce-scatter -- local_map redistribute train_step

核心动作: 由 4.2 的 ShardingConfig + local_map 在每层线性层前后自动触发 redistribute。进列并行线性前 all-gather 序列(SP 粒度 -> CP 粒度),行并行输出 partial 经 reduce-scatter 求和并切回 SP 粒度。

# 进 wq_b/wkv_b 前:in_src SP [1,512,7168] -> in_dst full [1,1024,7168] (all-gather, 512->1024)
# 列并行 forward 本身无通信,各 rank 算自己的半头(64/128)
# 出 wo 后:partial [1,1024,7168] -> reduce-scatter -> [1,512,7168] (求和+切序列 1024->512)

通信: all-gather(序列 512->1024)+ reduce-scatter(求和+切 1024->512)。动态: 每层每微批。async TP 开启时这些通信与计算重叠(4.3)。

4.12 PP 边界 p2p 通信 train_step

核心动作: 由 4.7 建好的 pp_schedule(Interleaved1F1B)在 stage 间点对点传 hidden(前向)/grad(反向),DTensor 传局部分片再重建。

# pipeline_parallel.py:40-62 (DTensor 跨阶段重建回调 _build_get_mesh_callback)
# 前向:stage0 -> stage1:hidden [1,512,7168] (SP 局部分片)
# 反向:stage1 -> stage0:grad [1,512,7168] (同 shape)
# 不 gather 全量,DTensor 直接传 local 再按 sender placement 重建

通信: p2p send/recv(hidden 前传 + grad 后传)。动态: 每微批。

4.13 反向 + FSDP grad reduce-scatter train_step

核心动作: 每层 backward 后 FSDP2 自动 reduce-scatter 梯度并 reshard 参数;TP/CP/EP 的对偶通信在反向各自发生。

# fsdp.py:27-41 disable_fsdp_gradient_division:梯度除法由 loss÷gvt 负责,不靠 FSDP 自动除
# 每层 backward 完成后 FSDP2 自动:
#   1. g = reduce_scatter(grad)  # 跨 fsdp/efsdp 组归约 + 分片回 dense 1/32 / expert 1/32
#   2. 参数 reshard(丢弃完整参数,释放显存)
# 反向通信:TP 列并行 grad all-reduce / TP 行并行 grad all-gather
#           CP K/V grad reduce / EP dispatch 反向 combine / PP p2p 传 grad

通信: reduce-scatter(梯度归约 + 分片回 dense 1/32 / expert 1/32)。动态: 每微批反向现算。

4.14 clip_grad_norm + AdamW train_step

核心动作: 8 微批梯度累加后,clip_grad_norm_ 在 pp_mesh 上 all-reduce 求全局范数,然后每 rank 在本地分片上更新。

# trainer.py:804-814
grad_norm = clip_grad_norm_([...所有 stage 参数...], max_norm, pp_mesh=pp_mesh, ep_enabled=True)
self.optimizers.step()      # AdamW 在每 rank 的 dense 1/32 / expert 1/32 分片上更新(仅本地)
self.lr_schedulers.step()
# utils.py: total_norm.full_tensor() 跨 fsdp 归约;pp_mesh all-reduce 跨 stage 求和

通信: all-reduce(梯度范数 跨 PP stage,且 EP 启用时跨 EP 处理)。AdamW 本身无通信。静态: AdamW 状态与参数同分片。

5三句话总结

① 初始化只做一次(静态):外层 pipeline_llm 先按 PP 把 61 层切 3 段(21/20/20);再对每个 stage 跑 parallelize_deepseekv3--CP 包 attention(必须在 parallelize 前)-> model.parallelize 声明 TP/EP/SP(MLA 列/行+低秩 Q、路由专家按 E 切 256->128、SP local_map)-> async TP -> AC -> compile -> FSDP(dense 1/32、专家 efsdp 1/32)。全部定型,训练中不变。

② train_step 每步重复(动态):新数据被 CP 切成 1/4 序列、schedule 切成 4 个 PP 微批、激活在层间被 SP 切成 1/8;MoE 每层做 EP dispatch/combine(all-to-all 路由 token,top-8);前向在切好的权重上算,反向把梯度 reduce-scatter 回 dense 1/32 / expert 1/32,AdamW 在本地分片上更新。

③ 每次 fwd/bwd 的 shape 链:[1,1024] tokens -> [1,512,7168] SP 激活 -> MLA 半头 Q [1,1024,64,192] + K/V 全量 [1,4096,64,128] -> MoE EP 路由 [1,512,7168] -> hidden [1,512,7168] 跨 stage -> 末阶段 2 块 logits [1,1024,64640] -> 标量 loss(CE 和 ÷ global_valid_tokens=262144)。

本页以 DeepSeek V3 671B(192 GPU 示意配置:TP2/SP2/CP4/PP3/EP2/dp_shard8)为准;模型结构依据 torchtitan/models/deepseek_v3/(_671b:dim=7168/61层/256专家/低秩Q),代码依据 main 分支(parallelize.py / pipeline_parallel.py / context_parallel.py / fsdp.py / sharding.py / moe_sharding.py / token_dispatcher.py / trainer.py)。注意:同系列 gpu_view_training_flow.html 仍为 Llama3-8B 配置,如需对齐请单独转换。
