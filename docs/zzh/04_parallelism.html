1. ParallelDims 与设备网格 Mesh

所有并行都建立在 ParallelDims（distributed/parallel_dims.py）之上。它由 ParallelismConfig + world_size 构造，描述六个并行维度的乘积必须等于 world_size：

# parallel_dims.py
dp_replicate · dp_shard · cp · tp · pp · ep == world_size
# 其中 dp_shard=-1 表示「用剩余 rank 自动填满」

build_mesh() 从一张 1D 的 world 网格出发，展开（unflatten）出带名字的子网格。命名轴（MeshAxisName）是理解一切的钥匙：

轴名含义由谁用
pp流水线并行PP 切分
dp_replicate复制式 DP（DDP/HSDP 的复制轴）DDP / HSDP
dp_shard / fsdp分片式 DP（FSDP 轴；legacy 把 dp_shard·cp 折成 fsdp）FSDP
cp上下文并行（沿序列维）CP
tp张量并行TP / SP
ep / efsdp专家并行 / MoE 区的 FSDPEP / MoE
batchdp_replicate·dp_shard 的数据加载维dataloader 分片
lossdp_replicate·dp_shard·cp 的 loss 聚合维loss all-reduce

代码里拿到子网格的方式是 parallel_dims.get_mesh("tp") / get_optional_mesh(...)（禁用时返回 None）。

axis 与 dim 的命名铁律
axis 永远指 DeviceMesh 的轴（如 tp）；dim 指张量维或网格形状。代码、注释、文档严格区分，避免歧义。上游 PyTorch API（如 mesh_dim_names）保留原拼写，但在 torchtitan 自有代码里统一用 axis。

2. 数据并行：FSDP / HSDP

由 apply_fsdp_to_decoder（distributed/fsdp.py）落地，核心是 PyTorch FSDP2 的 fully_shard。所有稠密与 MoE decoder 共用此函数。

  • FSDP：仅 dp_shard > 1 → 用 fsdp 网格。
  • HSDP：dp_replicate > 1 且 dp_shard > 1 → 网格带 dp_replicate 轴，权重在 replicate 轴内复制、在 shard 轴内分片。
  • 权重绑定：若 enable_weight_tying，把 tok_embeddings / norm / lm_head 合成一个 FSDP 单元，避免重复 all-gather。
  • MixedPrecisionPolicy：参数用 mixed_precision_param（默认 bf16），归约用 mixed_precision_reduce（默认 fp32）。
  • reshard_after_forward："default" 在 PP 下默认不 reshard（避免每 microbatch 重复 all-gather）；"always"/"never" 显式控制。
# fsdp.py （稠密块）
fully_shard(model.tok_embeddings, **fsdp_config, reshard_after_forward=...)
for layer_id, block in model.layers.items():
    fully_shard(block, **fsdp_config, reshard_after_forward=...)
fully_shard(model, **fsdp_config)
disable_fsdp_gradient_division(model)   # 关掉自动梯度除法，改由 global token 数归一化
EP 下的显式预取
当 ep > 1，MoE 的 D2H 同步会干扰 FSDP 隐式预取，因此 apply_fsdp_to_decoder 显式设置 forward/backward 的 set_modules_to_*_prefetch，把相邻 transformer block 串成预取链。

3. 张量并行 + 序列并行 (TP/SP)

TP 沿隐藏维（colwise/rowwise）切分线性层；SP 是 TP 的伴生优化：沿序列维切分激活，用 ring/all-gather 在 attention/FFN 边界重聚，从而把 LayerNorm/RMSNorm 也分到各 rank 上计算（否则 norm 输入需 Replicate，TP rank 间要通信）。

  • enable_sequence_parallel=True 为默认；切分声明写在 ShardingConfig 里（见 05 §声明式切分）。
  • attention 的 wo 与 FFN 的 w2 做 reduce-scatter 到 Shard(1)（SP）；其余激活 Replicate 或 Shard(1)。
  • 异步 TP（enable_async_tensor_parallel）要求 model 被 compile，设 torch._inductor.config._micro_pipeline_tp=True，让 TP 通信与计算微流水线重叠。
seq_len 整除约束
开启 SP 时 seq_len 必须被 tp 整除；开启 CP 时（load balancer 默认开启）必须被 2·cp 整除。Trainer.__init__ 会显式校验。

4. 流水线并行 (PP)

由 pipeline_llm（distributed/pipeline_parallel.py）落地，基于 torch.distributed.pipelining：

1算元数据　_get_pipeline_metadata：虚拟 stage 数、每层权重（首/末级各减 1 层，因为 embedding/output 更重）
2拆模块　_generate_llm_fqn_per_model_part / module_fqns_per_model_part 决定每个 stage 含哪些 FQN；_split_module 深拷贝并裁剪出 per-stage chunk
3建 PipelineStage　每个 PP rank 按 _get_pp_rank_to_stage_indices_mapping 取自己的 stage 集合
4逐 stage 应用 SPMD　对每个 model_part 调 parallelize_fn（FSDP/TP/AC/compile）
5建 schedule　_build_pipeline_schedule：1F1B / Interleaved1F1B / ZeroBubble 等；microbatch = local_batch / pipeline_parallel_microbatch_size
PP 的约束
  • 虚拟 stage 数必须能被 pp 整除。
  • 单 stage 调度（如 1F1B）要求每 rank 恰好 1 stage；looped 调度（如 Interleaved1F1B）要求每 rank ≥ 2 stage。
  • PP 与 VarlenAttention 不兼容（须用 FlexAttention 后端）。
  • 权重共享（weight tying）与 PP 不兼容。

5. 上下文并行 (CP)

CP 沿序列维把长序列切到多个 rank，attention 内部用 ring/load-balanced all-gather 收集 K/V，使每个 rank 只需算自己那一段序列的完整 attention（基于 FlashAttention 的 varlen/CP 实现）。

  • apply_cp_to_forward 在 Module.parallelize() 之前包裹 attention 的 forward（FlexAttention 用 flex_cp_allgather，SDPA 用 DTensor Shard(1)）。
  • prepare_context_parallel_input（在 post_dataloading_process 内调用）沿序列维切分 inputs/labels/positions/masks。
  • 负载均衡：headtail（SDPA）/ ptrr（FlexAttention）/ None。
CP 与 FSDP 的关系
即使「全局 batch=1 没有 DP」，只要用了 CP 就仍应用 FSDP（FSDP 轴 = dp_shard·cp），以复用其权重 all-gather 与梯度 reduce-scatter。这保证 CP 激活的权重分片语义正确。

6. 专家并行 (EP) 与 MoE

MoE 层里，专家被切到 ep 个 rank（与 dense 区共享同一批物理设备，约束 dp_shard·cp·tp == efsdp·ep）。

  • efsdp = dp_shard·cp·tp / ep：MoE 区的 FSDP 分片度。
  • apply_fsdp_to_decoder 对 MoE block 用 shard_placement_fn：专家走 edp_mesh，非专家参数走 dp_mesh；专家数 < FSDP 度时用 Shard(1) 避免 padding。
  • MoE 负载均衡（aux-loss-free）通过优化器 step 前的 hook 更新 expert bias（见 06 §优化器）。

7. 激活重算 (AC)

由 distributed/activation_checkpoint.py 提供三种策略（通过 activation_checkpoint 配置字段选择）：

策略行为
SelectiveAC（默认）按 op 选择性保存：保存昂贵的 compute/comm op（SDPA、linear、all-reduce、MoE dispatch…），其余重算；每两个 mm 强制重算一个以平衡显存/算力
FullAC整个 transformer block 在反向时重算
MemoryBudgetAC让编译器 partitioner 按内存预算在 compute/显存间权衡（必须编译 model）
AC 与数值一致性
AC 是「非计算类改动」，按 CLAUDE.md 要求，开启/更换 AC 策略必须让 --debug.seed=42 --debug.deterministic 下的 loss 与改动前逐位一致（或用 C4 验证收敛）。

8. torch.compile

CompileConfig 控制是否编译、编译哪些组件（model / loss）。apply_compile 在 AC 包裹之后、FSDP 之前对 model 编译；loss 的编译在 BaseLoss._maybe_compile 里。AC 必须在 compile 之前（这样编译能看见 wrapped 后的图）。

9. 三种 SPMD 后端

parallelism.spmd_backend 决定张量如何被切分和类型检查，影响 Module.parallelize() 与 mesh 的折叠方式：

后端特点
default传统 torchtitan 路径；fsdp 把 dp_shard·cp 折成单一轴；in-band 只保留 tp/ep
full_dtensor全 DTensor 路径；FSDP 用 dp_mesh_dims 显式声明 dp_shard+cp 折叠；SPMD 校验更严格
spmd_types基于 spmd_types 的类型系统；forward/backward 全程做 SPMD 类型检查（debug.spmd_typechecking）；dp 把 dp_replicate·dp_shard 折成单一逻辑轴
同一份 ShardingConfig，三种后端
声明式切分（SpmdLayout）的好处就在这里：模型代码只写一次 placement 声明，Module.parallelize() 在运行时根据 spmd_backend 选择 DTensor / spmd_types 的落地实现。这也是为什么 CLAUDE.md 鼓励「声明式而非命令式」并行。

10. 组合与约束

# 常见组合示例
# 8B 单节点：FSDP 分片
--parallelism.data_parallel_shard_degree=8
# 70B：TP8 + FSDP
--parallelism.tensor_parallel_degree=8
# 405B：TP8 + 异步 TP + float8
--parallelism.tensor_parallel_degree=8 --parallelism.enable_async_tensor_parallel
# 5D 并行：PP × (DP_rep × DP_shard × CP × TP) × EP
--parallelism.pipeline_parallel_degree=4 --parallelism.data_parallel_replicate_degree=2 \
--parallelism.tensor_parallel_degree=4 --parallelism.context_parallel_degree=2 \
--parallelism.expert_parallel_degree=8
改并行代码时的铁律（来自 distributed.md 规则）
1) 永远显式校验 mesh 轴与 placement，绝不假设 1D mesh；2) 文档化每个 to_local/local_map 的 grad_placements；3) 考虑所有并行组合，bug 报告要带并行配置；4) 模型无关代码放 distributed/；5) 改动收敛行为要强理由 + 充分测试。
