torchtitan/ 目录结构 · 一页速览

torch 2.12 · 三组件分离(模型定义 / 并行编排 / 训练循环)+ 实验区 + 基础设施 · 颜色对应组件归属

torchtitan/ ├── train.py ← 入口:解析配置、建并跑 Trainer ├── trainer.py ← Trainer:训练循环主控 ├── __init__.py │ ├── config/ 【配置系统】配置树 + tyro CLI 覆盖 │ ├── manager.py ← ConfigManager:--module/--config + <sec>.<key>=<val> │ ├── configs.py ← ParallelismConfig / TrainingConfig 等 │ ├── configurable.py ← Configurable:build() 递归实例化 │ ├── function.py ← ModelConfigConverter(如 Float8 转换) │ └── override.py ← @override 工厂机制 │ ├── protocols/ 【抽象协议】接口契约 │ ├── module.py ← Module(nn.Module+Configurable)+ parallelize 递归 │ ├── model_spec.py ← ModelSpec:模型+并行函数打包 │ ├── model.py ← BaseModel │ ├── sharding.py ← ShardingConfig(声明式切分) │ └── state_dict_adapter.py │ ├── models/ 【模型定义】与并行无关,注重可读 │ ├── common/ ← 共享:attention/moe/feed_forward/rope/decoder │ ├── llama3/ deepseek_v3/ qwen3/ qwen3_5/ │ ├── gpt_oss/ flux/ (model+sharding+parallelize+config_registry) │ └── utils.py ← 参数量/FLOPs 统计 │ ├── distributed/ 【并行编排】施加并行的辅助函数 │ ├── fsdp.py ← apply_fsdp_to_decoder(FSDP2+专家分流) │ ├── tensor_parallel.py ← async TP / NoParallel │ ├── pipeline_parallel.py ← pipeline_llm(PP 切 stage+schedule) │ ├── context_parallel.py ← apply_cp_to_forward / cp_shard │ ├── parallel_dims.py ← ParallelDims + mesh(efsdp 推导) │ ├── activation_checkpoint.py / compile.py │ ├── full_dtensor.py / spmd_types.py ← SPMD 后端 │ └── deepep/ minimal_async_ep/ ← EP 通信后端 │ ├── components/ 【训练组件】通用训练部件 │ ├── dataloader.py optimizer.py lr_scheduler.py loss.py │ ├── checkpoint.py metrics.py tokenizer.py validate.py │ ├── lora.py checkpoint_utils.py │ └── quantization/ ← Float8 等 │ ├── experiments/ 【实验区】独立实验,单向依赖 core │ ├── graph_trainer/ ← 编译图训练(SimpleFSDP+graph pass) │ ├── torchft/ ← 容错(fault tolerance) │ ├── transformers_modeling_backend/ ← HF 模型训练 │ ├── rl/ ← 强化学习(GRPO+vLLM rollout) │ └── forge/ ← 轻量训练引擎(后训练拼装) │ ├── overrides/ 【@override 模块】运行时替换 Configurable ├── hf_datasets/ 【数据集】HF 数据加载适配 ├── observability/ 【可观测】structured_logger / tracing ├── ops/ 【自定义算子】 └── tools/ 【工具】logging / utils
入口
train.py · trainer.py
解析配置、驱动训练循环。Trainer 拿到 config 后按字段各取所需。
配置 config/
配置树 + tyro CLI 覆盖(非 TOML)
manager / configs / configurable / override · config_registry 函数返回 Trainer.Config,tyro 覆盖 <sec>.<key>=<val>
协议 protocols/
抽象接口契约
module / model_spec / sharding · Module=nn.Module+Configurable;ModelSpec 打包模型+并行函数;ShardingConfig 声明切分
①模型 models/
模型定义,与并行无关、注重可读
common/ + llama3/deepseek_v3/qwen3/gpt_oss/flux · 每模型:model.py(结构)+sharding.py+parallelize.py+config_registry.py
②并行 distributed/
施加并行的编排函数
fsdp / tensor_parallel / pipeline_parallel / context_parallel / parallel_dims · CP 包装→parallelize→async TP→AC→compile→FSDP
③组件 components/
通用训练循环部件
dataloader / optimizer / lr_scheduler / loss / checkpoint / metrics / tokenizer · Configurable,可被 override 替换
实验 experiments/
独立实验区,标准宽松,单向依赖 core
graph_trainer · torchft · transformers_modeling_backend · rl · forge · 复用 core 模型定义,只换训练范式
基础设施
overrides/ hf_datasets/ observability/ ops/ tools/
@override 模块 · HF 数据集 · structured logger · 自定义算子 · logging/utils
①模型定义 ②并行编排 ③训练循环 配置 协议 实验 基础设施
三组件经 config_registry 分离又组装: 模型定义(config)·并行编排(函数引用)·训练循环配置(通用字段)分别挂到 Trainer.Config / ModelSpec 的不同字段,代码物理分离、逻辑正交,只在 config_registry 拼成可运行的 Trainer.Config。
① 模型定义 models/ — 纯结构,零并行依赖,不知 NCCL 存在
② 并行编排 distributed/ + parallelism 字段 — 函数,依赖模型但不改模型
③ 训练循环 trainer.py + components/ — 通用,经 config 字段配置
一句话:train.py 入口 → trainer.py 跑循环;models 定义模型(①)、distributed 施加并行(②)、components 提供训练部件(③),三者经 config_registry 组装、protocols 抽象解耦;experiments 在旁做实验不污染 core。
