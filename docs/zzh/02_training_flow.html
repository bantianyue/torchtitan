2. 细化 A：Trainer.__init__ 初始化顺序

图 2 · 构造 Trainer 的真实顺序。注意 PP 与 非PP 在「并行化」处分叉（蓝线），但都汇聚到「权重初始化」。

顺序为何重要
并行化必须在 init_weights 之前、在 optimizer.build 之前；apply_overrides 必须在所有组件构建前；step/ntokens_seen 必须在 checkpointer.load 之前（它们本身就是要被检查点恢复的状态）。CLAUDE.md 要求「改 setup 前先读 Trainer.__init__ 顺序」。

3. 细化 B：train() 主循环

图 3 · 主循环：左向回边表示 step++ 后回到 while 判断（灰色循环）。数据耗尽时跳出。

def train(self):
    self.checkpointer.load(step=config.checkpoint.load_step)
    loaded_step = self.step
    with config.profiler.build(...) as profiler:
        data_iterator = self.batch_generator(self.dataloader)
        while self.should_continue_training():       # step < training.steps
            self.step += 1
            self.gc_handler.run(self.step)
            try:
                self.train_step(data_iterator)
            except DataloaderExhaustedError:
                break
            self.checkpointer.save(self.step, last_step=(self.step == steps))
            if validator.should_validate(self.step):
                self.validator.validate(self.model_parts, self.step)
            profiler.step()
            if self.step - loaded_step == 1:       # 首步后收紧通信超时
                dist_utils.set_pg_timeouts(...)
为什么只在首步后收紧超时？
前若干步包含 lazy init 与编译开销，超时设宽（comm.init_timeout_seconds）；第一个真实 step 完成后，调用 set_pg_timeouts(train_timeout_seconds) 把通信超时收紧到更严格的值，避免卡死时等待过久。
batch_generator：数据留在 CPU
它是无限迭代器，从 dataloader 取 batch 后不立即上 GPU，yield 回调用方。梯度累积期间逐 microbatch 上 GPU，利于显存管理；途中数据耗尽会抛 DataloaderExhaustedError，整步取消。

4. 细化 C：train_step（梯度累积）

图 4 · 一个 train_step = 一次全局梯度更新，内部累积 gradient_accumulation_steps 个 microbatch。

global_valid_tokens 为什么关键
FSDP 的自动梯度除法被 disable_fsdp_gradient_division 关闭（见 06 组件），改为用全局有效 token 数手动归一化。因此 loss 先 sum 再 / global_valid_tokens，跨 rank 的总和才是正确均值。

5. 细化 D：forward_backward_step

图 5 · 非 PP 路径直白（单模型 part 跑前向+loss+反向）；PP 路径把前向/反向交给 pp_schedule.step()，末级 rank 才持有真实 loss。

def forward_backward_step(self, *, input_dict, labels, global_valid_tokens):
    inputs, labels, extra_kwargs = self.post_dataloading_process(input_dict, labels)
    if parallel_dims.pp_enabled:
        with self.train_context():
            targets, losses = (labels, []) if self.pp_has_last_stage else (None, None)
            if self.pp_has_first_stage:
                self.pp_schedule.step(inputs, **extra_kwargs, target=targets,
                                      losses=losses, loss_kwargs=...)
            if self.pp_has_last_stage:
                loss = torch.sum(torch.stack(losses)).to(self.device)
            else:
                loss = torch.tensor([-1.0], device=self.device)
    else:
        with self.train_context():
            pred = model_parts[0](inputs, **extra_kwargs)
            loss, _ = self.loss_fn(pred, labels, global_valid_tokens)
            loss.backward()
    return loss
PP 下非末级 rank 的 loss 是占位
只有末级 stage 持有 labels 与 targets，能算出真实 loss；其他 rank 返回 -1.0 占位，仅在末级做有意义的聚合。这也是为什么 train_step 里 loss 聚合要区分 DP/CP 是否开启。

6. 细化 E：post_dataloading_process

图 6 · 在「数据加载之后、模型前向之前」做后处理，把原始 dict 转成模型需要的形式。

  • 拆 input/labels： inputs = input_dict["input"]；其余键作为模型前向 kwargs。
  • 构建 attention masks： 若使用 Flex/Varlen attention 且提供了 positions，调用 model.get_attention_masks(positions)。
  • Context Parallel 切分： cp 开启时 prepare_context_parallel_input 沿序列维切分 inputs/labels/positions。
  • SPMD 输入类型化： full_dtensor：parallelize_inputs；spmd_types：annotate_input_spmd_types。
  • 累计 ntokens_seen： CL 切分后按真实处理的 token 数累计（而非切分前序列长度）。

7. 细化 F：检查点与指标

图 7 · 每个 train_step 末尾的检查点与指标收尾。

  • 检查点： checkpointer.save(step) 判断是否满足保存条件（首步、interval、末步）；异步模式在 optim.step() 后先 maybe_wait_for_staging() 等后台搬运完成。详见 06 §检查点。
  • 指标： 仅当 metrics_processor.should_log(step) 为真才聚合与打印；跨 DP/CP 用 loss_mesh 做 all-reduce 求全局均值/最大值。详见 06 §指标。
  • 验证： 若 validator.enable 且 validator.should_validate(step)，在保存后调用 validator.validate(model_parts, step)。
