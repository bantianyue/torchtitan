0全貌与参数审计

DeepSeek V3 671B 是一个 MoE 解码器:61 层,前 3 层是 dense FFN,后 58 层是 MoE(256 路由专家 + 1 共享专家)。注意力用 DeepSeek 独有的 MLA(Multi-head Latent Attention) 低秩注意力,KV 经低秩压缩以省 KV cache;Q 也用低秩分解(wq_a+wq_b)。词表 129280,不 tying(embed 与 lm_head 各一份)。

总参数量671.0 B(active,本页审计值,与官方一致) 层数 / dense 层数61 / 3(层 0-2 dense,层 3-60 MoE) model dim (D)7168 vocab (V)129280 注意力头数 (H)128,每头 qk_nope=128 + qk_rope=64 = 192,v_head=128 Q 低秩 (q_lora)1536(wq_a: D→1536,wq_b: 1536→H·192) KV 低秩 (kv_lora)512(wkv_a: D→512+64,wkv_b: 512→H·256) 路由专家256 个,hidden=2048,每 token top-8(sigmoid + 组限路由 8 组/4 组) 共享专家1 个,hidden=2048(=moe_h·1) dense FFN hidden18432(仅前 3 层) RoPEComplexRoPE,仅作用于 qk_rope 64 维;YaRN scaling(40×,原长 4096→16384)
参数分布(审计): 路由专家权重占 97.4%(~653B,58 层 × 256 专家),embed 与 lm_head 各 0.93B,61 层注意力合计仅 ~1.7%(每层 187M),共享专家 ~2.5B。即"绝大多数参数在 MoE 专家里"。

1整体结构图(端到端前向)

下图自上而下是 DeepSeekV3Model.forward 的完整数据流:token → embed → 61 个 TransformerBlock → final norm → lm_head → logits。每个 block 内部是两段残差(图中每段的蓝色/绿色长条即这两段):x = x + Attention(RMSNorm(x)) 与 x = x + FeedForward/MoE(RMSNorm(x))。dense 层(0-2)的第二段是 FeedForward;MoE 层(3-60)的第二段换成 MoE(路由专家 + 共享专家),两种层的注意力段完全相同(MLA)。

图 1-1:DeepSeek V3 671B 端到端结构。Dense 层(0-2)用 SwiGLU FFN;MoE 层(3-60)用"路由专家 + 共享专家"替换 FFN,注意力层两种都用 MLA。

2TransformerBlock:两段残差的定义

每个 block 由 DeepSeekV3TransformerBlock 定义,继承自 TransformerBlock。它持有 attention(MLA)、两个 RMSNorm(attention_norm/ffn_norm),以及 feed_forward(dense 层)或 moe(MoE 层)二者之一。forward 就是标准两段残差。

# torchtitan/models/deepseek_v3/model.py:149-183
class DeepSeekV3TransformerBlock(TransformerBlock):
    """DeepSeek V3 Transformer block with attention and feed-forward layers."""

    @dataclass(kw_only=True, slots=True)
    class Config(TransformerBlock.Config):
        pass

    def __init__(self, config: Config):
        super().__init__()
        self.attention = config.attention.build()        # MLA 注意力
        self.attention_norm = config.attention_norm.build()
        self.ffn_norm = config.ffn_norm.build()

        self.moe_enabled = config.moe is not None
        if self.moe_enabled:
            assert config.moe is not None
            self.moe = config.moe.build()                # MoE 层(58 层走这里)
        else:
            assert config.feed_forward is not None
            self.feed_forward = config.feed_forward.build()  # dense FFN(3 层走这里)

    def forward(self, x, attention_masks, positions=None):
        x = x + self.attention(self.attention_norm(x), attention_masks, positions)
        if self.moe_enabled:
            x = x + self.moe(self.ffn_norm(x))
        else:
            x = x + self.feed_forward(self.ffn_norm(x))
        return x

关键点:dense 层与 MoE 层的唯一结构差异就是 feed_forward vs moe。两者都通过同一套两段残差 forward。这个设计由 _build_dsv3_layers(见第 6 节)统一生成:层 id < n_dense_layers(=3)给 feed_forward,否则给 moe。

3MLA 注意力(Multi-head Latent Attention)

MLA 是 DeepSeek V3 区别于 Llama 的核心。它把 KV 压缩到低秩潜空间(kv_lora_rank=512),再按需展开成多头 K/V,大幅省 KV cache;Q 也做低秩分解(wq_a 降到 1536 再 wq_b 升回)。只有 qk_rope=64 维走 RoPE,其余 qk_nope=128 维不旋转。

图 3-1:MLA 注意力数据流。Q 走低秩分解(wq_a→q_norm→wq_b),KV 走低秩压缩(wkv_a→kv_norm→wkv_b),仅 64 维 rope 部分旋转,最后 FlexAttention + wo 输出。

MLA forward 源码(model.py:92-146)

def forward(self, x, attention_masks, positions=None):
    bsz, seqlen, _ = x.size()

    # Query 投影:低秩分解 wq_a → q_norm → wq_b
    if self.q_lora_rank == 0:
        q = self.wq(x)                       # 671B 走不到(671B q_lora_rank=1536)
    else:
        q = self.wq_a(x)                     # [B,L,7168] → [B,L,1536]
        q = self.wq_b(self.q_norm(q))         # → [B,L,128*192]

    with spmd.local():
        q = q.view(bsz, seqlen, -1, self.qk_head_dim)   # [B,L,128,192]
    q_nope, q_pe = torch.split(q, [self.qk_nope_head_dim, self.qk_rope_head_dim], dim=-1)

    # KV 投影:低秩压缩 wkv_a → split → kv_norm → wkv_b
    kv = self.wkv_a(x)                        # [B,L,7168] → [B,L,576]
    kv, k_pe = torch.split(kv, [self.kv_lora_rank, self.qk_rope_head_dim], dim=-1)

    q_pe, k_pe = self.rope(q_pe, k_pe.unsqueeze(2), positions)  # 仅 64 维旋转
    q = torch.cat([q_nope, q_pe], dim=-1)

    kv = self.wkv_b(self.kv_norm(kv))             # [B,L,512] → [B,L,128*256]
    with spmd.local():
        kv = kv.view(bsz, seqlen, -1, self.qk_nope_head_dim + self.v_head_dim)
        k_nope, v = torch.split(kv, [self.qk_nope_head_dim, self.v_head_dim], dim=-1)
        k = torch.cat([k_nope, k_pe.expand(-1, -1, k_nope.size(2), -1)], dim=-1)

    output = self.inner_attention(q, k, v, attention_masks=attention_masks, scale=self.softmax_scale)
    output = output.view(bsz, seqlen, -1)
    return self.wo(output)                  # [B,L,16384] → [B,L,7168]
MLA vs 标准 MHA: 标准 MHA 每层 K/V 是 [B,L,128,128](per-head 全量);MLA 把 KV 压到 [B,L,512] 潜空间,只在 attention 前用 wkv_b 展开。这使 KV cache 缩到 ~1/8,是 671B 长上下文推理的关键。代价是多了一次 wkv_b matmul,但训练时算力充足、显存更值钱,故划算。

4MoE 层:路由专家 + 共享专家

58 个 MoE 层用 MoE 模块替换 dense FFN。结构:router 给每 token 选 top-8 专家 → token dispatcher 把 token 派发(EP 时 all-to-all)到专家所在 rank → 256 个路由专家各算 SwiGLU → combine 汇回 → 与 1 个共享专家(全 token 都过)的输出相加。

图 4-1:MoE 层数据流。router 选 top-8 → dispatch/combine(EP all-to-all)做路由专家 SwiGLU → 与共享专家相加。共享专家全 token 都过,弥补路由稀疏。

MoE 核心源码(moe.py:358-389 构造 + 390-510 forward 摘要)

class MoE(Module):
    @dataclass(kw_only=True, slots=True)
    class Config(Module.Config):
        num_experts: int = 8
        experts: GroupedExperts.Config
        router: TokenChoiceTopKRouter.Config
        load_balance_coeff: float | None = 1e-3
        shared_experts: FeedForward.Config | None = None
        seq_dim_tp_sharded: bool = False

    def __init__(self, config):
        super().__init__()
        self.experts = config.experts.build()        # 256 路由专家(GroupedExperts)
        self.router = config.router.build()          # TokenChoiceTopKRouter
        self.shared_experts = config.shared_experts.build() if config.shared_experts else None
        # auxiliary-loss-free 负载均衡 buffers:
        self.register_buffer("expert_bias_E", torch.zeros(num_experts))      # [256],persistent
        self.register_buffer("tokens_per_expert_E", torch.zeros(num_experts)) # [256],不持久

    def forward(self, x_BLD):
        # 1. router 选专家(float32 算分,sigmoid,node-limited,top-8)
        topk_scores_BLK, topk_expert_ids_BLK, scores_BLE = self.router(x_BLD, self.expert_bias_E)

        # 2. 路由专家:dispatch → grouped_mm SwiGLU → combine
        out_BLD = self.experts(x_BLD, topk_scores_BLK, topk_expert_ids_BLK,
                            num_local_tokens_per_expert_E, ...)

        # 3. 共享专家:所有 token 都过的 dense SwiGLU(与 combine 并行)
        shared_out_BLD = self.shared_experts(x_BLD) if self.shared_experts else None

        # 4. 合并
        if shared_out_BLD is not None:
            out_BLD = out_BLD + shared_out_BLD
        return out_BLD

路由专家 GroupedExperts 的权重与计算(moe.py:35-110)

class GroupedExperts(Module):
    def __init__(self, config):
        self.num_experts = config.num_experts            # 256
        # 三个权重都是 [E, F, D] / [E, D, F] 形状的参数(分组矩阵乘)
        self.w1_EFD = nn.Parameter(torch.empty(num_experts, hidden_dim, dim))  # [256,2048,7168]
        self.w2_EDF = nn.Parameter(torch.empty(num_experts, dim, hidden_dim))  # [256,7168,2048]
        self.w3_EFD = nn.Parameter(torch.empty(num_experts, hidden_dim, dim))  # [256,2048,7168]
        self.token_dispatcher = config.token_dispatcher.build()

    def _experts_forward(self, x_RD, num_tokens_per_expert_E):
        # SwiGLU,用 torch._grouped_mm 按 expert offset 分组算
        h_RF = F.silu(torch._grouped_mm(x_RD, w1_EFD.transpose(-2,-1), offs=offsets_E))
        h_RF = h_RF * torch._grouped_mm(x_RD, w3_EFD.transpose(-2,-1), offs=offsets_E)
        return torch._grouped_mm(h_RF, w2_EDF.transpose(-2,-1), offs=offsets_E)

路由器 TokenChoiceTopKRouter(moe.py:173-323 摘要)

class TokenChoiceTopKRouter(Module):
    @dataclass(kw_only=True, slots=True)
    class Config(Module.Config):
        num_experts: int
        gate: Linear.Config
        num_expert_groups: int | None = None      # 671B = 8
        num_limited_groups: int | None = None # 671B = 4(节点限路由)
        top_k: int = 1                          # 671B = 8
        score_func: Literal["softmax", "sigmoid"] = "sigmoid"
        route_norm: bool = False              # 671B = True
        route_scale: float = 1.0              # 671B = 2.5

    def forward(self, x_BLD, expert_bias_E=None):
        with torch.autocast(dtype=torch.float32):    # float32 算分,稳负载均衡
            scores_BLE = self.gate(x_BLD)              # [B,L,256]
        scores_BLE = torch.sigmoid(scores_BLE)
        if self.num_expert_groups is not None:        # node-limited:8 组选 4 组
            scores_BLE = self._get_node_limited_routing_scores(scores_BLE)
        _, topk_expert_ids_BLK = torch.topk(scores_BLE, k=self.top_k, dim=-1)  # top-8
        topk_scores_BLK = scores_BLE.gather(-1, topk_expert_ids_BLK)
        if self.route_norm:                      # 归一化(671B 开)
            topk_scores_BLK = topk_scores_BLK / (topk_scores_BLK.sum(-1, keepdim=True) + 1e-20)
        topk_scores_BLK = topk_scores_BLK * self.route_scale
        return topk_scores_BLK, topk_expert_ids_BLK, scores_BLE
node-limited 路由(671B 特有): 256 个专家分 8 组(每组 32,对应物理节点),每 token 只在得分最高的 4 组里选 top-8。这把跨节点 all-to-all 通信限制在 4 个节点内,显著降通信量。route_scale=2.5 + route_norm=True 是 DeepSeek 的路由缩放归一化。

5Dense FFN 与基础组件

FeedForward — SwiGLU(feed_forward.py:34-54)

dense 层(0-2)与共享专家都用 FeedForward,标准 SwiGLU:w2(silu(w1(x)) · w3(x))。三者都是 Linear(无 bias)。

class FeedForward(Module):
    @dataclass(kw_only=True, slots=True)
    class Config(Module.Config):
        w1: Linear.Config
        w2: Linear.Config
        w3: Linear.Config

    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))
dense 层 FFNw1/w3: [18432,7168],w2: [7168,18432] · hidden=18432 共享专家 FFNw1/w3: [2048,7168],w2: [7168,2048] · hidden=2048(=moe_h×1)

Decoder 整体容器(decoder.py:229-284 摘要)

class DeepSeekV3Model(Decoder):
    def __init__(self, config):              # Decoder.__init__
        self.tok_embeddings = config.tok_embeddings.build()   # Embedding
        self.layers = ModuleDict()
        for i, layer_config in enumerate(config.layers):
            self.layers[str(i)] = layer_config.build()        # 61 个 block
        self.norm = config.norm.build()                       # final RMSNorm
        self.lm_head = config.lm_head.build()                 # Linear
        if self.enable_weight_tying:  # 671B = False,不 tying
            self.tok_embeddings.weight = self.lm_head.weight

    def forward(self, tokens, positions=None, attention_masks=None):
        h = self.tok_embeddings(tokens)            # [B,L] → [B,L,7168]
        for layer in self.layers.values():         # 61 个 block 依次过
            h = layer(h, attention_masks, positions)
        h = self.norm(h)                          # final RMSNorm
        if self._skip_lm_head: return h          # chunked loss 时跳过
        return self.lm_head(h)                  # [B,L,7168] → [B,L,129280]

def _671b(attn_backend, moe_comm_backend, non_blocking_capacity_factor=None):

    q_lora_rank = 1536; moe_hidden_dim = 2048; num_shared_experts = 1
    dense_hidden_dim = 18432; rope_dim = 64; num_experts = 256; n_dense_layers = 3

    layers = _build_dsv3_layers(
        n_layers=n_layers, n_dense_layers=n_dense_layers, dim=dim, n_heads=n_heads,
        q_lora_rank=q_lora_rank, kv_lora_rank=512,
        qk_nope_head_dim=128, qk_rope_head_dim=rope_dim, v_head_dim=128,
        mscale=1.0, dense_hidden_dim=dense_hidden_dim, moe_hidden_dim=moe_hidden_dim,
        num_experts=num_experts, num_shared_experts=num_shared_experts,
        router_top_k=8, router_score_func="sigmoid",
        router_num_expert_groups=8, router_num_limited_groups=4,  # node-limited
        router_route_scale=2.5, router_route_norm=True,
        attn_backend=attn_backend, moe_comm_backend=moe_comm_backend, ...,
        rope=ComplexRoPE.Config(dim=rope_dim, max_seq_len=4096*4, theta=10000.0,

_build_dsv3_layers:dense/MoE 自动分流(__init__.py:160-262 核心)

def _build_dsv3_layers(*, n_layers, n_dense_layers, dim, ...):
    """层 id < n_dense_layers 给 dense FFN,否则给 MoE。"""
    layers = []
    for layer_id in range(n_layers):
        attn_cfg = _make_dsv3_attn_config(layer_id=layer_id, dim=dim, n_heads=n_heads,
                                          q_lora_rank=q_lora_rank, ...)   # MLA config
        if layer_id < n_dense_layers:                  # 0,1,2 → dense
            ffn_cfg = make_ffn_config(dim=dim, hidden_dim=dense_hidden_dim, ...)  # SwiGLU
            moe_cfg = None
        else:                                        # 3..60 → MoE
            ffn_cfg = None
            moe_cfg = make_moe_config(
                num_experts=num_experts,
                router=make_router_config(dim=dim, num_experts=num_experts, top_k=router_top_k,
                                          score_func=router_score_func,
                                          num_expert_groups=..., num_limited_groups=..., ...),
                experts=make_experts_config(dim=dim, hidden_dim=moe_hidden_dim,
                                            num_experts=num_experts, comm_backend=moe_comm_backend, ...),
                shared_experts=make_ffn_config(dim=dim,
                                               hidden_dim=moe_hidden_dim * num_shared_experts, ...),
            )
        layers.append(DeepSeekV3TransformerBlock.Config(
            attention=attn_cfg,
            attention_norm=RMSNorm.Config(normalized_shape=dim, ...),
            ffn_norm=RMSNorm.Config(normalized_shape=dim, ...),
            feed_forward=ffn_cfg, moe=moe_cfg,
        ))
    return layers
设计要点: dense 与 MoE 的差异被封装在"block config 的 feed_forward vs moe 字段"里,DeepSeekV3TransformerBlock.forward 用一个 if self.moe_enabled 分流。新增模型只需写 config 工厂,不改 forward 逻辑。MLA 的低秩结构则封装在 _make_dsv3_attn_config + Attention.forward 里,与 MoE 完全正交。

7Config 树 -> Module 树:代码怎么完整表示这个模型

前面六节讲的是"671B 长什么样"。这一节回答更根本的问题:一个 671B、含上千个子模块的模型,源码里只有几十个类,是怎么完整表示出来的? 答案是 torchtitan 的核心抽象:Config 树与 Module 树同构,靠递归 build() 互相转换。

7.1 为什么看起来"只有 1 个 Config"?--其实是 1 棵 Config 树

DeepSeekV3Model 内部只定义了一个嵌套 Config(model.py:191),但它继承 Decoder.Config(decoder.py:70-84),后者的字段类型本身又是别的 Config:

class DeepSeekV3Model(Decoder):
    @dataclass(kw_only=True, slots=True)
    class Config(Decoder.Config):       # 根 Config
        dim: int = 2048
        vocab_size: int = 102400

# decoder.py:70-84  Decoder.Config(根 Config 的字段在父类里)
@dataclass(kw_only=True, slots=True)
class Config(BaseModel.Config):
    dim: int
    vocab_size: int
    lm_head: Linear.Config            # 子 Config(引用)
    tok_embeddings: Embedding.Config  # 子 Config(引用)
    norm: RMSNorm.Config              # 子 Config(引用)
    layers: list                    # list[Block.Config] = 61 个子 Config!
    enable_weight_tying: bool = False
关键认知: Config 是个 dataclass,它的字段是对其他 Config 实例的引用。所以 1 个 DeepSeekV3Model.Config 内部其实嵌套了上千个 Config 节点。"每类一个嵌套 Config"是源码组织方式,不是配置数量。

图 7-1:671B 的 Config 树(局部)。根 Config 的字段是对子 Config 的引用,层层嵌套成一棵与模型同构的树。

7.2 递归 build():Config 树实例化成 Module 树

转换靠 Configurable.Config.build()(configurable.py:134-160)的递归。两个机制:

① 自动接线 _owner(configurable.py:162-180):每个类定义嵌套 Config 时,__init_subclass__ 自动把 Config._owner 指向所属类。于是 DeepSeekV3Model.Config._owner = DeepSeekV3Model、Attention.Config._owner = Attention……所有 Config 都"知道"自己该 build 成谁。

② build() 调所属类的 __init__,而 __init__ 又对子 Config 字段调 build()--递归到底:

# configurable.py:134-160  Config.build() 的核心
def build(self, **kwargs):
    if self._owner is None:
        raise NotImplementedError(...)
    return self._owner(config=replace(self))   # 调所属类的 __init__(config=...)

# decoder.py:229-240  Decoder.__init__ 对每个子 Config 再调 build()
def __init__(self, config):
    self.tok_embeddings = config.tok_embeddings.build()   # Embedding.Config -> Embedding
    self.layers = ModuleDict()
    for i, layer_config in enumerate(config.layers):
        self.layers[str(i)] = layer_config.build()          # Block.Config -> Block(继续递归!)
    self.norm = config.norm.build()
    self.lm_head = config.lm_head.build()

# model.py:158-170  Block.__init__ 继续递归到 attention / moe
def __init__(self, config):
    self.attention = config.attention.build()   # Attention.Config -> MLA(再递归 build wq_a/wq_b...)
    self.moe = config.moe.build()                 # 或 feed_forward = config.feed_forward.build()

所以 model_config.build() 一次调用,递归实例化整棵上千个 Module 的树。Config 树和 Module 树同构--每个 Config 节点对应一个 Module 节点,FQN 一致(如 layers.5.attention.wq_b)。

build() 同时挂载两个横切关注点

每个 Module.Config 还带 param_init 和 sharding_config 两个字段(module.py:56-70),build() 时挂到实例上。这让权重初始化和并行切分与结构定义解耦:

# module.py:56-70  Module.Config.build() 挂载横切字段
def build(self, **kwargs):
    instance = Configurable.Config.build(self, **kwargs)   # 实例化 Module
    if self.param_init is not None:
        instance._param_init = self.param_init            # 权重初始化器字典
    if self.sharding_config is not None:
        instance._sharding_config = self.sharding_config    # 并行切分声明
    return instance
param_init形如 {"weight": partial(nn.init.trunc_normal_, std=depth_scaled_std(0.02, layer_id))}。671B 用 _depth_init(layer_id) 让每层 std 随深度缩放;专家用 _depth_experts_init(w1 固定 std=0.02,w2/w3 随深度)。init_states 时按参数名查表初始化。 sharding_config声明该参数/buffer 在 TP/EP/SP 下的放置(见 sharding.py)。build 时不切分,留给 parallelize() 在训练初始化时按声明施加。

7.3 完整生命周期:从 ModelSpec 到可训练模型

trainer 把上述机制串成一条流水线(trainer.py:280-433):

图 7-2:从 ModelSpec 到可训练模型的完整生命周期。Config 树贯穿始终,build() 是 Config->Module 的转换点。

init_states:递归初始化权重(module.py:72-119)

def init_states(self, *, buffer_device=None):
    # 1. 先递归所有子 Module(广度优先队列)
    queue = list(self.children())
    while queue:
        child = queue.pop(0)
        if isinstance(child, Module):
            child.init_states(buffer_device=buffer_device)   # 递归
        else:
            queue.extend(child.children())                    # 穿过 compile/AC 包装
    # 2. 再初始化自己的参数(用 build() 时挂上的 _param_init 字典)
    self._init_self_parameters()
    # 3. 再初始化自己的 buffer(如 RoPE cache、MoE 计数器)
    self._init_self_buffers(buffer_device=buffer_device)

_init_self_parameters(module.py:160-190)按参数名查 _param_init 字典:有就用对应初始化器(如 671B 的 _depth_init(layer_id)),没有就回退到 reset_parameters()(nn.Linear 等 PyTorch 默认)。这样 671B 每层权重能按层 id 做深度缩放初始化,而无需在 forward 里写任何初始化代码。

一句话总结: DeepSeekV3Model.Config 不是"唯一的配置",而是配置树的根节点。每个类各自定义一个嵌套 Config,通过 dataclass 字段引用串成与模型同构的树;build() 递归把 Config 树实例化成 Module 树;init_states 递归初始化、parallelize 递归切分。结构(param_init)、并行(sharding_config)、初始化(_param_init)三件事在 Config 层声明、在 Module 层施加,完全解耦--这就是 torchtitan 用几十个类表示上千子模块的完整机制。
结构总结: DeepSeek V3 671B = Decoder 容器(61 个 DeepSeekV3TransformerBlock)+ embed/lm_head。每 block = MLA 注意力 + (dense FFN 或 MoE)。MLA 用 Q/KV 双低秩压缩省显存;MoE 用"256 路由专家 top-8 + 1 共享专家"实现稀疏激活(每 token 只激活 9 个专家,但总参数 671B)。代码上 dense 与 MoE、MLA 与 MoE 完全正交,靠 config 工厂组合。
