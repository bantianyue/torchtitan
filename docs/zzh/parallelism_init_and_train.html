0 总览:五个策略在初始化和训练期的位置

先建立全局坐标。所有并行都挂在 Trainer.__init__(trainer.py:243)和 train_step(trainer.py:813)上。 五个策略没有独立的"启动器",它们是被 网格(mesh)定义 + 模型 parallelize + 数据预处理 + train_step 各环节 组合启用的。 下图左侧是初始化时间线,右侧是训练时间线,颜色对应各策略。

图 0 · 五大策略在初始化与训练中的挂载位置

先讲一个贯穿全文的基础:网格定义(parallel_dims.py:203 build_mesh)把 1D world 网格 unflatten 成带名字的轴 —— pp、batch(=dp_replicate*dp_shard,数据加载用)、cp、tp,外加 dp_replicate、fsdp(=dp_shard*cp,legacy 折叠)/dp_shard、 ep/efsdp,以及 loss(=batch*cp,loss 聚合用)。大小为 1 的轴用 fake backend(不建真实进程组),fsdp 例外——即使度为 1 也用真实后端,因为 fully_shard 需要安装 MixedPrecisionPolicy(parallel_dims.py:186-201)。 这是后面每个策略"初始化"的落点:每个策略都拿到属于自己的子网格,再去做参数切分/数据切分。

1DP 数据并行:没有独立初始化的"隐形"并行

1.1 初始化做了什么

torchtitan 没有单独一段"DDP 初始化"代码。DP 以三种形态存在,全部在网格定义 + FSDP 分片时一并完成:

  • 网格定义:batch = dp_replicate * dp_shard(parallel_dims.py:272)——数据加载轴;每个 DP rank 的"身份"就是 batch 网格上的 rank。
  • dataloader 按 DP rank 取数:StatefulDataLoader(dp_rank, dp_world_size=batch_degree)(dataloader.py:88-104),由 Trainer.__init__ 传入 batch 网格的 rank/size(trainer.py:279-283, 524-542)。每个 DP rank 读数据流的不同位置,checkpoint 时也按 dp_rank 保存 dataloader 状态(dataloader.py:140-147)。
  • dp_shard 维度:权重分片交给 FSDP(见第 2 节),梯度在 shard 轴内 reduce-scatter。
  • dp_replicate 维度:若 >1,fully_shard 的网格带上 dp_replicate 轴 → HSDP:权重在 replicate 轴复制、shard 轴分片(fsdp.py:319-322 打印 "Applied HSDP to the model")。
  • loss 聚合轴:loss = flatten(batch, cp)(parallel_dims.py:284),训练中 loss 指标在此轴上 all-reduce。

图 1 · DP 初始化:网格定义 + dataloader 分数据 + FSDP/HSDP 分权重

1.2 训练过程中做了什么

  • 取数:batch_generator 从 dataloader 逐批取出,每 DP rank 拿自己那份(trainer.py:616-643)。
  • 全局有效 token 数:本地 valid tokens 在 batch 网格上 all-reduce(trainer.py:838-842),loss 归一化用全局数,而不是 DP 除法——这正是 FSDP 梯度不除以 DP 度的原因(fsdp.py:27-41)。
  • 梯度归约:发生在 FSDP 反向阶段 —— 分片轴内 reduce-scatter(见第 2 节),复制轴内 all-reduce(HSDP)。
  • loss 指标聚合:loss mesh(dp_replicate x dp_shard x cp)上 all-reduce SUM 得 global_avg_loss、MAX 得 global_max_loss(trainer.py:896-919)。
  • optimizer:每 DP rank 在本地参数(分片或副本)上独立 step,无跨 DP 通信(trainer.py:882)。

图 2 · DP 训练期:独立取数、独立前反向,梯度归约与 loss 聚合是唯二跨 DP 的通信

2FSDP 全分片数据并行:初始化 fully_shard 分片,训练期 all-gather / reduce-scatter

2.1 初始化做了什么

入口 apply_fsdp_to_decoder(fsdp.py:110),由每个模型的 parallelize.py 调用(如 llama3/parallelize.py:80-90)。核心是 PyTorch FSDP2 的 fully_shard。发生在模型还在 meta device、权重尚未初始化的时候,只切分布局、不搬数据。

  • 混合精度策略:MixedPrecisionPolicy(param_dtype, reduce_dtype, cast_forward_inputs=False)(fsdp.py:165-169)——决定权重 all-gather 与梯度归约的通信精度,与训练 dtype 分离。
  • FSDP 单元划分(fsdp.py:194-310):每个 transformer block 一个 fully_shard(fsdp.py:209-308);tok_embeddings 单独(194-199);[norm, lm_head] 合并成一个单元(202-207,最后两层会被 FSDP 立即 prefetch,合并不浪费);最终整模型再包一层(310)。权重绑定时 tok_embeddings/norm/lm_head 合成一个单元,避免重复 all-gather(180-192)。
  • reshard_after_forward 策略:"default" = not pp_enabled(fsdp.py:66-78)——PP 开启时默认不 reshard,避免每个微批都 all-gather(见训练期)。
  • MoE 特殊切分:shard_placement_fn 让专家权重用独立网格 edp_mesh(EP>1 时)或 Shard(1)(FSDP 度 > 专家数时防 padding)(fsdp.py:216-302)。
  • 关闭梯度除法:disable_fsdp_gradient_division 把梯度除以因子设为 1.0(fsdp.py:27-41, 316)——torchtitan 的 loss 用全局 token 数归一化,不需要 FSDP 的 1/DP 缩放。
  • CPU offload / symm_mem:可选(fsdp.py:173-174, 312-313)。
  • EP 显式 prefetch:EP>1 时设置 set_modules_to_forward_prefetch / set_modules_to_backward_prefetch(fsdp.py:326-366)。
  • 网格:legacy 后端用 ["dp_replicate","fsdp"](HSDP)或 ["fsdp"](纯 FSDP),其中 fsdp = dp_shard * cp —— CP rank 也在 FSDP 组内(llama3/parallelize.py:74-77, parallel_dims.py:217-220)。

图 3 · FSDP 初始化:单元划分 + fully_shard 分片布局

2.2 训练过程中做了什么

FSDP2 通过 fully_shard 给每个单元安装 __call__ hook,在前向/反向的自然时机插入通信。per-microbatch 视角:

  • 前向:进入某 FSDP 单元前,all-gather 把完整权重收集到本 rank → 本地完整计算 → 离开时按策略 reshard(丢弃其他分片,释放显存)。reshard_after_forward=True 时每层前向后就 reshard,显存最优;下一层前向再 all-gather,两段时间重叠(prefetch)。
  • 反向:每单元梯度算完后 reduce-scatter:各 rank 只保留自己分片的梯度,同时完成 DP 求和。因此 optimizer 更新的是本地分片参数,无需任何跨 rank 通信(trainer.py:882)。
  • PP 协同:PP 开启时 reshard_after_forward 默认 False(fsdp.py:66-78)——权重在前向保持展开,避免每个 PP 微批重复 all-gather(微批之间权重不变)。
  • 权重绑定:绑定单元合并后,一次 all-gather 同时服务 embedding 与 lm_head(fsdp.py:180-192)。
  • grad_norm 计算:FSDP 参数的梯度是 DTensor,clip_grad_norm_ 通过 full_tensor() 在分片轴内归约得到全局范数(utils.py:639-642)。

图 4 · FSDP 训练期:一层内的一次前向/反向生命周期

3TP 张量并行:初始化声明式切分,训练期层内集体通信

3.1 初始化做了什么

TP 是唯一"声明式"的并行:模型配置文件里写清楚每个参数/激活的 placement(sharding.py),Module.parallelize() 递归执行。

  • 声明:set_llama3_sharding_config(llama3/sharding.py:25-75)填写每个子模块的 ShardingConfig:wqkv / w1 / w3 列并行(weight Shard(0),decoder_sharding.py:65-73);wo / w2 行并行(weight Shard(1),输出 Partial → SP 时 reduce-scatter 到 Shard(1),否则 all-reduce 到 Replicate,decoder_sharding.py:76-93);attention 内部用 local_map 切 Q/K/V(decoder_sharding.py:190-231);norm 在 SP 下权重 Replicate、激活 Shard(1)(96-111);tok_embeddings / lm_head 词表并行(decoder_sharding.py:270-287)。
  • 执行:Module.parallelize(protocols/module.py:248-294)递归每个带 sharding_config 的模块:(1) _distribute_states:distribute_tensor(param, mesh, placements) 把参数变成 DTensor(module.py:331-411,此时在 meta device,只建布局);(2) 把 forward 包成 输入 redistribute -> local_map 本地计算 -> 输出 redistribute(module.py:287-294, 452-496)。local_map 同时声明了 in_grad_placements,保证反向梯度也是正确的 DTensor 布局。
  • 词表并行细节:Embedding.forward 在本地词表分片做 lookup + mask,再由模块边界的 redistribute 完成 all-reduce(embedding.py:39-79);ScaledBiasRowwiseLinear 的 bias 除以 TP 度(linear.py:61-71)。
  • async TP:若 enable_async_tensor_parallel,设置 Inductor 的 _micro_pipeline_tp = True(要求编译,tensor_parallel.py:102-115)——通信与计算按微块重叠,训练期生效。

图 5 · TP 初始化:声明式配置 -> distribute_tensor 切参数 + local_map 包 forward

3.2 训练过程中做了什么

  • 前向:每层数据流:输入按声明 redistribute(列并行输入复制、行并行输入切分)→ 本地矩阵乘 → 输出 Partial。列并行(wqkv/w1/w3)的输出是各 rank 的部分结果,由下一层的行并行(wo/w2)消费;行并行输出必须归约:enable_sequence_parallel=True(默认)时 reduce-scatter 到 Shard(1),下一层 norm 直接在序列分片上算(SP);否则 all-reduce 到 Replicate(decoder_sharding.py:76-93)。
  • 反向:local_map 的 in_grad_placements 保证梯度按同样的布局流动:行并行权重的梯度来自 Partial 输入梯度的 all-reduce/reduce-scatter,列并行权重梯度是本地输入梯度与部分输出梯度的乘积(各 rank 独立,无需通信)。
  • async TP:开启时 Inductor 把通信(如 all-reduce)按 micro-pipeline 切块,与计算交错重叠(tensor_parallel.py:102-115,需要 torch.compile)。
  • 与 FSDP 协同:TP 切完的参数是 DTensor,fully_shard 在其上再按 fsdp 轴分片;TP 轴的梯度在 TP 组内已归约,FSDP 只处理 fsdp 轴的归约。

图 6 · TP 训练期:层内"列并行出 Partial -> 行并行归约"的数据流与反向布局

4PP 流水线并行:初始化物理切层 + 建调度,训练期 1F1B 微批调度

4.1 初始化做了什么

入口 pipeline_llm(pipeline_parallel.py:65-141),在 trainer.py:397-422 调用。PP 最先执行,因为切层之后,每个 stage 还要再跑一遍 TP/FSDP/AC/compile(pipeline_parallel.py:109-123)。

  • 切分计划:_get_pipeline_metadata 计算虚拟 stage 数(pipeline_parallel.py:194-264);_generate_llm_fqn_per_model_part 把 tok_embeddings + layers + norm + lm_head 尽量均匀分给每个 stage(366-476)。
  • 物理切层:_split_module deepcopy 整模型后删掉不属于本 stage 的模块(479-538);PipelineStage(chunk, stage_idx, ..., group=pp_mesh.get_group("pp")) 包装成 stage(581-649)。本 rank 只持有自己 stage 的模块。
  • stage 内再并行:每个 stage chunk 上再跑 parallelize_fn(TP/FSDP/AC/compile)(pipeline_parallel.py:109-123)。
  • 调度器:_build_pipeline_schedule(267-363):默认 1F1B(configs.py:188),微批数 n_microbatches = local_batch_size / pipeline_parallel_microbatch_size;batch 必须能被微批整除,否则报错(pipeline_parallel.py:306-311)。
  • 权重初始化:每个 stage to_empty + init_weights(trainer.py:427-433);set_determinism 让 PP 组内 seed 相同、PP 组间 seed 不同(utils.py:153+, distinct_seed_mesh_dims=["pp"]),保证各 stage 参数独立初始化。

图 7 · PP 初始化:物理切层 -> 每 stage 内再并行 -> 调度器

4.2 训练过程中做了什么

  • 取微批:每梯度累积步取 num_pipeline_parallel_microbatches 个微批(trainer.py:826-833);输入只进 first stage,labels 只进 last stage(trainer.py:789-794)。
  • 调度执行:pp_schedule.step()(trainer.py:798-805)按 1F1B 执行:前向阶段把管道填满(每个 stage 逐微批前向,stage 间 p2p send/recv 激活);随后每个 stage 交替执行前向/反向,每个微批的反向完成后把梯度 p2p 回传给前一 stage。last stage 计算 loss(_scalar_loss_fn, pipeline_parallel.py:327-329)。
  • loss:非 last stage 返回 -1(trainer.py:811);last stage 汇总各微批 loss(trainer.py:808-810)。
  • grad clip:跨 PP stage 的梯度范数要 all-reduce(SUM for L2 / MAX for inf)才能得到全局范数(utils.py:644-650)。
  • optimizer:每个 stage 有自己的 optimizer 实例,只更新本 stage 参数(trainer.py:503)。
  • FSDP 协同:PP 下 FSDP 默认不 reshard(见 2.2);微批间权重保持展开,省掉每微批的 all-gather(fsdp.py:66-78)。

图 8 · PP 训练期:1F1B 调度的前向/反向交替与 p2p 通信

5CP 上下文并行:初始化包装 attention,训练期序列切分 + K/V all-gather

5.1 初始化做了什么

  • 包装 attention:apply_cp_to_forward(context_parallel/api.py:35-112)替换每个 attention 的 forward(llama3/parallelize.py:47-52)。按 attention 类型分两条路:
    • FlexAttention:包一层 cp_forward,进入前把 K/V all-gather 成全局(flex_cp_allgather(k, v, dim=1)),再调用原 forward(api.py:57-78)。Q 保持本地分片。
    • SDPA:启用 CP dispatcher(_enable_context_parallel_dispatcher()),把 Q/K/V 包成 Shard(1) 的 DTensor(DTensor.from_local),输出再 to_local()(api.py:80-101)。
  • 时序:CP 包装必须在 Module.parallelize() 之前(llama3/parallelize.py:47-54 注释),这样 CP 层会被 TP 的 local_map 包在内层,两层并行叠加正确。
  • 约束:seq_len 必须能被 2 * cp 整除(load balancer 需要,parallel_dims.py:699-706;trainer.py:262-270 校验)。
  • FSDP 协同:legacy 后端下 fsdp = dp_shard * cp,CP rank 也参与权重 all-gather/reduce-scatter(parallel_dims.py:217-220)。

图 9 · CP 初始化:按 attention 类型替换 forward

5.2 训练过程中做了什么

  • 序列切分:post_dataloading_process 调用 prepare_context_parallel_input(trainer.py:701-710):cp_shard 把 inputs / labels / positions 沿序列维(seq_dim=1)切到各 CP rank(api.py:114-163, 166-301)。
  • mask 切分:attention masks(BlockMask)只切 Q 序列维(dim 2),KV 维不动(api.py:276-299)。
  • 负载均衡:HeadTailLoadBalancer(SDPA,默认)或 PTRRLoadBalancer(FlexAttention)处理序列不均(api.py:217-264, configs.py:213 默认 "headtail")。
  • 前向:每个 CP rank 只计算自己那截序列;attention 内 all-gather K/V 后本地计算完整注意力(FlexAttention 路径的 all-gather 在包装的 forward 里,api.py:73)。序列维的剩余计算(FFN/norm)完全本地。
  • loss 聚合:loss mesh 包含 cp(parallel_dims.py:284, 391),loss 指标在 dp x cp 上一起归约(trainer.py:896-919)。
  • 有效 token 数:labels 在 CP 切分后计数,ntokens_seen 反映本 rank 真实处理的 token(trainer.py:712-714)。
